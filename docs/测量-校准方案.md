# 测量校准方案（Pr 概览条实测前必须先过）

> 由来：用户 2026-10-25 要求「为了测试准确，先检查工具本身的准确性，并设计一个可复现的情况，
> 让我（用户）在你测完之后能检查」。本文就是那套检查。
> 配套脚本：`tools\pr-env-check.py`、`tools\make-calib-bar.py`、`tools\pr-bar-scan.py`、`tools\px-measure.py`。

## 〇、硬门禁：分辨率

**测量一律在 1280×800 @ 100%（dpi 1）下进行**（用户 2026-10-25 定的规矩）。1280×800 的截图能一屏看全、
坐标与 Pr 窗口一一对应，方便肉眼复核。

所有测量脚本第一步调用：

```
python tools\pr-env-check.py          # 不符则 exit 2
env: 1280x800 dpi=96 (1.00x)   expect 1280x800 dpi=96
env: PASS
```

不符时打印实测值并 `exit 2`，测量**必须停止**，不允许"先跑完再解释"。

## 一、判据的基本单位：1 px 的时间当量

概览条上 1 px 对应多少秒，取决于素材长度：

| 素材 | rw=1240 px | 1 px = | 折合帧（30 fps） |
|---|---|---|---|
| 30 s | 1240 | 0.024 s | 0.73 帧 |
| 5 min | 1240 | 0.242 s | 7.3 帧 |
| 15 min | 1240 | 0.726 s | 21.8 帧 |
| 30 min | 1240 | 1.452 s | 43.5 帧 |
| 60 min | 1240 | 2.905 s | 70 帧（23.976 fps 下 0.028 s/帧 ⇒ 104 帧） |

⇒ **所有精度判据都用「≤1 px」，不能写「≤1 帧」**（1 帧对长素材是不可能的）。
反过来，用户抱怨的「6 min 对不上 0 s」= 360 s ≈ 124 px，远大于任何工具误差 ⇒ 该差异**一定测得出**。

## 二、C1 扫描器精度（离线，已完成 ✅）

**目的**：把"像素扫描"与"Pr"解耦 —— 若 C1 通过，后续误差只可能来自 Pr 侧操作。

**布置（可复现）**：`tools\make-calib-bar.py` 在**已知坐标**画出三种真实形态：

| 图 | 形态 | 真值 |
|---|---|---|
| `docs\测量-校准\calib-居中.png` | 条 x=20..1260、两环各自独立（t0=30 s、t1=90 s / dur=300 s） | l=144.00 r=392.00 |
| `docs\测量-校准\calib-贴边.png` | 左环压条端（t0=0、t1=150 s） | l=20.00 r=640.00 |
| `docs\测量-校准\calib-最小.png` | 两环重叠成一个亮块（t0=150、t1=152 s，环心距 8.27 px < 环径 13） | l=640.00 r=648.27 |

真值同时写进同名 `.gt.json`。

**结果（2026-10-25）**：

```

calib-居中  144.00/392.00    144.00/392.00     +0.00/+0.00   30.000/90.000   PASS  1px=0.242s [two-ring]

```

**你自己怎么查**：`python tools\px-measure.py docs\测量-校准\calib-居中.png` → 左键点两个环心 →
状态栏给原图像素坐标，(144,400) 与 (392,400) 就是标准答案；任何一张图的读数与 .gt.json 不一致，就是工具错。

**C1 已经抓到的两个真坑（不校准必然出事）**：
1. **环伸出条端 6 px**：Pr 全片时环心压在条端，环的最外像素在条外 —— 若把"最左亮像素"当条端，x0 会偏 −6 px。
   修法：环心离边缘 ≤ cr+2 时，认定"环心即条端"。
2. **最小档两环重叠成一个亮块**：只用"两个块中心"的算法在这个档直接失效（只找到 1 个块）。
   修法：单块时按 `l = 块左 + cr`、`r = 块右 − cr` 反推 —— 否则最小档数据全废，而最小档恰恰最关键。

## 三、C2 Pr 条端标定（真机，1 次）

**布置**：30 s 素材 → 双击概览条回全片（区间 = 0..30 s）。

**判据**：`pr-bar-scan.py --dur 30` 读出 `x0/x1`，同时 `t0≈0 t1≈30`（|Δ| ≤ 1 px 当量 = 0.024 s）；
Pr 时间码读数为 `00:00:00:00` 与 `00:00:30:00`。

**你怎么查**：截图里肉眼可见两环压在条两端；时间码与我的 t0/t1 数字一致。

## 四、C3 已知区间的交叉验证（真机，4 档，最能说服）

**布置**：用**键盘把区间设成精确值**（这步完全可复现，谁做都一样）：

1. 源监视器时间码框输入 `00:00:10:00` → 回车（播放头到 10 s）
2. 按 `I` 设入点
3. 输入 `00:00:20:00` → 回车，按 `O` 设出点

⇒ 区间 **10~20 s**（u=1/3、c=0.5，居中）。再重复做出 0~10 s（贴头）、20~30 s（贴尾）、以及一个最小档。

**判据**：扫描器反算的 `t0/t1` 与键入值差 ≤ 1 px 当量（0.024 s ≈ 0.7 帧）。

**你怎么查**：同样的键盘操作你自己能做出来；读数与屏幕上时间码逐位对比。

## 五、C4 重复性（真机）

- 同一位置**连截 3 张** ⇒ 三次读数必须**完全一致**（0 px 抖动）。
- **重拖到同一目标 2 次** ⇒ 两次读数差 ≤ 2 px（这是拖动机构本身的精度，不是扫描器的）。

**你怎么查**：我把三张截图都留在 `_tmp\prshots\`，文件名带序号，你任挑两张看环位置是否一样。

## 六、C5 贴边语义（真机）

**布置**：区间 0~10 s（贴片头）vs 5~15 s（居中，同跨度）。

**判据**：贴头档 `l == x0`（±1 px，钉住），居中档 `xc ≈ 0.25+…` 随 k 变化；
两者跨度 `w` 在有相同的 u 下必须相同（宽度只看 u，不看位置）。

**你怎么查**：两条读数并排看，位置变了但 w 不变就对了。

## 七、全部通过的判定

C1 + C2 + C3 + C4 + C5 全绿才允许采正式数据（5 个片长 × 7 档）。
任何一项超差：先修工具，不采数据。报告写在 `docs\测量-校准报告.md`，逐项列真值 / 实测 / 差 / 判定。
