# Pr 概览条缩放序列实测（2026-10-28）

> 目的：验证 mpv 侧概览条映射模型 `w = u^p`、`p = ln(W_min/rw) / ln(V_min/dur)`。
> 本文记录 3 个片长素材、2 种播放头位置、共 36 个测量点。
> 结论：模型成立。三素材第 1 步的 `p` 与公式值相差 0.0%~1.0%。

## 〇、一句话结论

**「每按一次 `=`，Pr 把可视区间的跨度乘 1/1.888」+「宽度 = 跨度的 p 次方」**，
两件事拼起来就能完整复现 Pr 的概览条。之前所有「−5% 的系统偏差」全部来自
把 1.888 当成 2.0。

| 项 | 值 |

| 素材 | `reference\标尺素材-30s-30fps.mp4`（900 f）、`-5min-`（9000 f）、`-30min-`（54000 f） |
| 时间轴 | 轨道 x = 20.5 .. 1259.5（**rw = 1239**），概览条环心行 **y = 691~696** |
| 缩放下拉 | 「适合」= 全片 |

三片素材的 `W0`（全片环心距）都是 **1239.0**，轨道几何与片长无关。

## 二、方法：为什么不读可视跨度 V

早期方案想「点 ruler 两端读时间码，相减得 V」。**不可行**：全片时 1 px ≈ 43 帧
（54000/1239），点两端各有几十帧误差。

改为**只扫条宽 W，不读 V**：

1. 「适合」状态扫 `W0`
2. 按一次 `=`，扫 `W1`
3. 再按一次，扫 `W2` … 直到 W 不再变化（钳住）

判据落在「`ln(W_i)` 对 `i` 是否成直线」上。只要序列等比，幂律就成立；
比例系数同时给出 `p × ln(倍率)`。**这条路线完全不需要知道 V**。

读数工具：截 `CopyFromScreen` 全屏图，扫环壁中点。见 §六 的两个坑。

## 四、三个结论

### 4.1 宽度只取决于跨度，与播放头位置无关

3.3 与 3.4 是同素材、同缩放序列、只改播放头：

| 步 | W（中心） | W（偏心） | 差 |
|---|---|---|---|
| 0 | 1239.0 | 1239.0 | 0.0 |
| 1 | 771.0 | 771.0 | 0.0 |
| 2 | 478.0 | 478.5 | 0.5 |
| 3 | 295.0 | 295.0 | 0.0 |
| 4 | 180.0 | 180.0 | 0.0 |
| 5 | 108.0 | 108.5 | 0.5 |
| 6 | 63.0 | 63.5 | 0.5 |
| 7 | 35.0 | 35.0 | 0.0 |
| 8 | 21.0 | 21.0 | 0.0 |

最大差 0.5 px（扫描分辨率极限）。

### 4.2 位置 L 只取决于中心，且撞片头会被钳

| 步 | L（中心） | L（偏心） |
|---|---|---|
| 0 | 20.5 | 20.5 |
| 1 | 254.5 | **20.5** |
| 2 | 401.0 | **20.5** |
| 3 | 492.5 | 61.0 |
| 8 | 629.5 | 140.0 |

偏心时前两步左端死贴 20.5 —— 锚点在播放头，区间收缩时左端先撞片头被钳，
右端继续左移，宽度照常变小；第三步左端才离开片头。

**同一条宽度曲线、两条完全不同的位置曲线**，证明「宽度幂律」与「中心线性」
是两个独立分量。

### 4.3 p 命中公式，倍率是 1.888 不是 2

```
p = ln(W_min / rw) / ln(V_min / dur)     -- W_min=22, V_min=40, rw=1239
```

按每次缩 `a` 倍反推 `p = ln(W_i/W0) / (i × ln a)`，取 **a = 1.888**：

| 素材 | 实测 p（第 1 步） | 公式 p | 偏差 |
|---|---|---|---|
| 30 s | 1.308 | 1.295 | +1.0% |
| 5 min | 0.746 | 0.744 | +0.3% |
| 30 min | 0.559 | 0.559 | **0.0%** |

若沿用 `a = 2`，三素材会统一偏 −5%（1.232 / 0.70 / 0.528），且三者的**比值**
仍然精确（实测 1.232/0.528 = 2.333，模型 1.295/0.559 = 2.317）—— 说明偏差
是纯乘性的，即倍率错，不是模型错。

### 4.4 倍率随缩放深度递增，趋近 2.0

用 `p` 固定为公式值反推每下倍率（5 min）：

```
1.891 → 1.896 → 1.902 → 1.912 → 1.927 → 1.948 → 1.983
```

前 3 步只差 0.5%，后几步才明显。这是 Pr 内部实现，不是映射规律。
**mpv 侧不需要复刻**（mpv 用自己的比例步长 `tl_zoom_steps`）。

## 五、最窄环心距

三片素材的钳位值都是 **21.0 px**（30 s / 5 min / 30 min 一致）。
历史记录里的 22 px 与此在 1 px 内，口径相同（两环**圆心**距离）。
这与「最窄可视跨度 43~44 帧、与片长无关」是一致的。

## 六、两个必须记住的坑

### 6.1 环壁「跨对」会伪造出 10.5 px 的假最窄值

两环靠得很近时（W ≲ 30 px），一行里会出现 4 段环壁，相邻间隙分别约 7 / 12 / 7 px。
旧扫描器取「前两对」，把中间那组**跨对**（左环右壁 + 右环左壁）当成一个环，
算出 10.5 px。正确做法是取**首尾两对**（`pairs[0]` 与 `pairs[-1]`）。

若没发现这一点，会得出「Pr 最窄只有 10 px」的错误结论，进而否定 22 px 这条口径。

### 6.2 注入与截图通道

| 需求 | 可用手段 | 不可用 |
|---|---|---|
| 按 `=` / `-` | `_tmp\inj.ps1 -Action zoom / zoomout`（SendInput VK 0xBB / 0xBD） | `gui_key ` |
| 截图 | `inj.ps1 -Action shot`（抢前台后同进程 `CopyFromScreen`） | `gui_screenshot`（会激活 DSH 抢走前台） |
| 跳播放头 | `gui_click` 帧号框 + `gui_key ctrl+a` + `gui_type` + `gui_key enter` | 自建 SendInput 键盘（对 Pr 无效） |
| 滚轮 | python `mouse_event` 或 `gui_scroll` | — |

python 若要用 `SetCursorPos`，进程必须 DPI-aware（`SetProcessDpiAwareness(2)`），
否则坐标被按逻辑像素解释，滚轮全部打空。

## 七、复现命令

```powershell
# 复位到全片
& _tmp\inj.ps1 -Pid_ <pid> -Action zoomout -N 10
& _tmp\inj.ps1 -Pid_ <pid> -Action shot -Out _tmp\n0.png

# 逐步放大
for ($i=1; $i -le 9; $i++) {
  & _tmp\inj.ps1 -Pid_ <pid> -Action zoom -N 1
  Start-Sleep -Milliseconds 650
  & _tmp\inj.ps1 -Pid_ <pid> -Action shot -Out "_tmp\n$i.png"
}

# 扫描
python _tmp\rscan.py _tmp\n0.png _tmp\n1.png ...
```

## 八、对 mpv 的落地

| 量 | 取值 | 来源 |
|---|---|---|
| 宽度映射 | `w = u^p`，`u = (t1-t0)/dur` | §4.3 |
| 指数 | `p = ln(W_min/rw) / ln(minspan/dur)` | §4.3 |
| `W_min` | `22 × display-hidpi-scale` px | §5、P7 |
| `minspan` | `tl_min_frames = 40` 帧 | 既有 |
| 中心 | 线性 `xc = (t0+t1)/2/dur` | §4.2 |
| 撞片头 | 钳住（不越界） | §4.2 |

这样 `u_min` 恰好落在 `W_min` 上，**不需要任何视觉硬撑**，
「条缩不动」与「中间抓手消失」两个症状同时消失。
