# 第 9 条 设计方案（**已对齐，2026-10-12**）：可缩放时间轴 OSD + 面板拖动 / ✕ / −

> 状态：**讨论稿**。你在这份上直接改/加注释都行；定下来我再拆成 r44… 的步骤开始写。
> 原文两半：**A** mpv 侧新 OSD＝类 Pr 的**可缩放时间轴**（显示标记位置 / 点按跳转 / 自定义缩放区间 / 显示出入点）；
> **B** 鼠标党那套 **F2 按钮面板**加**拖动 / ✕ 关闭 / − 最小化**（最小化时 F2 变"还原"）。

## 一、时间轴：版式与几何

- **位置**：控制栏**正上方**（Pr 也是"时间轴在下、按钮在上"的堆叠关系，我们上下颠倒过来更顺眼：//Pr其实也是时间轴在上按钮在下
  栏在最底、时间轴在栏上面一行）
- **宽度**：与控制栏同宽（超出时按窗口宽度夹紧）；**高度** ≈ 26–30px（随 `bar_scale` 一起缩放）
- 三段内容（从左到右）：
  1. 左端 = **范围起点时间码**，右端 = **范围终点时间码**（Pr 也是把两端时间码摆在刻度带两端）

     //Pr是左端显示播放头显示时间，右端显示已选出入点区间长度(未选择时为源长度)，但是我们在这里已经在左上角默认显示和右上角做到区间范围了(F10)模式，所以你的建议是合理的；按照pr的风格，点击这些时间码应该可以自己输入跳转(比如按了之后时间码就变成编辑态输入hh:mm:ss:ff enter就可以跳)，这个可能比较难
  2. 中间 = **刻度带**：标记三角 + 出入点括号 + 区间底色 + 播放头竖线 + 0 / 结尾两条淡刻度
  3. 右端小按钮（可选）：`−` `+` `全`（缩小 / 放大 / 回到全域）

**定稿（2026-10-13，r45 已实现）**：宽 = 窗口 **84%**（原 62% 与下方控制栏"比例对不上"）；
高度 = `tl_scale × bar_scale` 基准（`tl_scale` 默认 **2.0**，**两个独立缩放因子**是用户要求的）；
自上而下 **6 行**：两端时间码 → 刻度标签 → 标记头型 → 刻度基线（**固定在块底部**）→ 概览条（**块最底部**，Pr 位置）。
播放头竖条与头型**共用中心线** `floor(x)+0.5`。

## 三、显示细节

- **标记**：**彩色盾形**（色值取共享色表 `marker-colors.json`，与 Pr 标记色一致），**比播放头瘦**（`mw_mk`）
  - **密集合并**：两个标记在 2px 内就只画一个（否则几百个标记会糊成一条实心带）
- **播放头**：**盾形**（尖端落在刻度基线上）+ 一条 30 透明度的竖线；**放大到一帧 ≥6px** 时另画一条
  "**当前显示帧**"蓝扁条 —— Pr 用它表示"监视器显示的是播放头这一帧的哪一侧"
- **概览 `⚪==⚪`**：在**刻度基线下面**（块最底部）= 深色轨道（可滑动范围）+ 亮段（可见范围）+ 两端圆；
  映射默认 **`bar`**（Pr 实测形态：宽度只看区间大小、中心按 k(u) 放大）；`linear` 才是所见即真实比例，`sqrt`/`pow` 是旧近似
- **刻度尺**：大刻度 + 小刻度 + 标签，**画在播放头竖条上层**（Pr 行为：刻度压住播放头）
  - ≥1s：时钟值档 `1,2,5,10,15,30` 秒/分…，每条**恒定 5 段**；标签 `MM:SS`（跨小时 `H:MM:SS`）
  - <1s：大刻度 = fps 的**整数因子且 ≥2 帧**，小刻度份数取 `{5,4,3,2}` 里第一个能整除的；标签 `SS:FF`
- **出入点**：`[` `]` 两个括号 + 区间内**淡色带**；"区间武装中"（Enter 从入点播）改用**绿色带**
- **不做**（本期）：波形、缩略图、拖拽标记、时间轴上的多轨

## 四、性能与重绘

- 时间轴**单独一个 overlay**（与 面板 / 帮助 / 徽标 / 控制栏 并列），**自己的 `time-pos` 观察者**，
  节流 **0.1s（10 Hz）**；控制栏保持原来的 0.2s
  - 理由：播放头要"看起来在走"，0.2s 会一跳一跳；ASS 载荷只有几十行，10 Hz 毫无压力
- 标记多时按"2px 合并"降载；合并后的密集区最多画 N 个（N 与带宽挂钩）

## 五、开关与状态

- **跟随控制栏**：`style='prbar'` 时 F2 一起开关（一次管"Pr 风格整套"）
- 选项：**`tl=yes/no`（默认 yes）**；**`tl_scale=2.0`**（时间轴自己的缩放，与 `bar_scale` 解耦）；
  **`tl_labels=true`**（刻度时间戳开关 —— Pr 没有时间戳，所以要能关）；
  **`tl_ov_map=bar`**（默认；`linear`/`sqrt`/`pow` 备用）；
  **`tl_ov_pin=px`**（默认；`time` 备用）—— 拖圆时"另一端"钉住什么：
  `px` = 钉住那一端的**像素**（该端时间跟着微调，Pr 上机实测左端漂 12~16 帧，用户 m00281 定论）；
  `time` = 钉住那一端的**时间**（圆在屏幕上会挪，20→5 跨度约 28 px）。
  两者互斥的根源是 bar 映射：宽度只由区间大小决定（`w=u^1.30`），位置由中心决定（`xc=0.5+(c-0.5)·k(u)`）
  **`tl_ov_edge=pin`**（默认；`pr` 备用）—— 区间贴片头/片尾时怎么映射：
  `pin` = 贴边那一端钉死在 0/1（`l=0,r=w`），跨进贴边那一帧会跳 6~21 px（映射两段规则不连续）；
  `pr` = 一律用中心公式再平移 clamp，跨入无阶跃，但贴边那端留 6 px 左右的缝。二者数学上不可兼得。
  **居中对称（两阶段，动态）**：判定用**当前区间**的 `pn=(tph-g.t0)/(g.t1-g.t0)`，进入 `|pn-0.5|<=0.02`、
  退出 `>0.05`（迟滞，状态 `gr.sym`）→ 拖动中区间收到播放头落中间就自动两圆对称，拖回去就回单动。
  进入判据除了窗口，还算**跨过** 0.5（`gr.pn_prev` 与当前 `pn` 分居 0.5 两侧）：0.02 窗口在 0~15 上只有 0.3 s，
  鼠标快拖一帧就跨过去，跨过之后再也不会回到窗口内 —— 这就是"有概率进不去"的另一半原因。
  对称跨度过 `TL.bar_solve_center` 反解，优先于 `tl_ov_pin`；只有 `sp > hi = min(2·tph, 2·(dur-tph))`
  （或居中后越过片边）才退回单动，**`sp == hi` 是合法解**（进入那一帧跨度往往正好等于它，判成触界就会"刚进就退"）。
  退回时把锚点换成当前像素并上锁 `gr.sym_block`（同动里 p 恒 0.5，不锁会每帧"进→触界→退"= 闪现+横跳），
  播放头离开窗口才解锁。播放头位置取抓起快照 `TL.grab.tph`（播放中不漂）。
  **拖圆判定顺序（每帧）**：① 对称（上面那条）→ ② 像素钉住 `bar_solve_px`（`tl_ov_pin=px`）→
  ③ 转嫁 `illegal`（缩小且会让播放头远离中点 ⇒ 钉住被抓端、另一端按鼠标位移反向跟手，`gr.trans` 一旦触发
  本次拖动内保持，回拖不切回，否则锚点从"被抓端"换回"另一端"必然跳一下）→ ④ 旧的时间钉住（兜底）。
  转向一律看**鼠标位移**（`gr.mx_prev`），不看鼠标与端点的相对位置：同动之后端点被搬到别处，回拖会被误判成缩小。
  **贴边不再跳**：px 反解越界时按贴边公式重解（`w=anchor 到片边距离`、`span=w^(1/pow)·dur`），
  贴边端钉 0/1、另一端不动 —— 所以 `tl_ov_edge` 在 px 口径下已无必要（保留作对照）
  **命中与可点范围**：概览圆的半径 `cr≈3.6·s` 导出到 `TL.geo.cr`；刻度带下界与概览条上界统一到
  `min(rl_y+1, y_ov-cr-2)`（圆顶），命中半径 `max(tl_hit_px, cr+6)`，贴边的圆再把内侧补一倍。
- 缩放范围 `UI.tl = {t0, t1}`，**默认 = 整片**；**跨重启记住**（用户拍板，见 §十一）

## 六、B 半：面板的 ✕ / − / 拖动

### ✕ 关闭（等价 F2）（✅ r47 已落地）

- 面板**标题行右侧**加 `✕` → 调 `toggle_panel(false)`，与 F2 完全同路
- 实现取舍：没有另画一个 ✕ 图标，而是把标题行原有的「OSD 显示/隐藏」按钮当 ✕ 用
  （同一个 handler、同一个 `toggle_panel`，文字比图标更能说清"再点一次会回来"）。

### − 最小化（✅ r47 已落地）

- 标题行右侧再加 `−` → 整个面板缩成**左下角一个小方块**，里面只剩 `＋`
  （实测：33×33 px，左上角在 OSD `(20, h-51)`，与窗口左下角留白一致）
- 点小方块 = 还原（走同一套 `PANEL_BUTTONS` + input section，鼠标区域由 `render_panel` 末尾统一注册）
- **最小化状态下按 F2 = 还原**（你原文的要求）—— 实现在 `toggle_panel` 开头拦一道，
  不是关闭：`if state == nil and style == 'panel' and UI.panel and UI.panel_min then … return end`
- 关闭面板时把 `panel_min` 清掉（"关掉再开"应给完整面板，不能让最小化粘住）
- 小方块在**左下**、标记模式徽标在**右下**，互不打扰
- **跨重启记住**（你 §九.7 拍板：都记住）→ `source-markers-ui.json` 里的 `panel_min`
- 只对按钮面板有效：Pr 风格控制栏没有面板，点 − 会提示"最小化只对按钮面板有效"

### 拖动（✅ r48 定稿，2026-10-22 用户拍板）

- **抓手**：面板**标题行左侧**一个 `⠿` 图标（`panel-drag`），不挤占现有的 帮助 / OSD 显示隐藏 / `−`。
- **为什么必须「点-移动-点」**：mpv 的输入只有**鼠标按下**事件、**没有松开**事件 —— 社区为此专门写了
  [mpv-pointer-event](https://github.com/christoph-heinrich/mpv-pointer-event)、
  [uosc 自建事件机制](https://deepwiki.com/tomasklaen/uosc/4.2-event-handling)；
  mpv 自带的"拖动窗口"是在**窗口层**实现的，脚本拿不到那个状态 ⇒ 纯脚本里"按住不放拖着走"**做不到可靠**。
  不引入第三方脚本（多一份外部依赖 + 许可问题）。
- **交互**：**点 `⠿` = 抓起 → 移动鼠标，`⠿` 跟着走 → 再点 `⠿` = 放下**；`ESC` = 取消、面板回原位。
  抓起时顶部提示一行「移动鼠标调整位置，点 ⠿ 放下（ESC 取消）」。
- **跟手口径**：`⠿` 与鼠标**同步移动** —— 抓起时记下「鼠标点 − ⠿ 中心」的偏移 `(dx, dy)`，之后
  `⠿中心 = 鼠标点 − (dx, dy)`，面板左上角再由 ⠿ 在面板内的固定偏移反推 ⇒ 抓在哪就跟到哪，
  面板不会"左上角跳到鼠标"。**不是**把面板左上角对到鼠标。
- **触边（定稿 A）**：**面板整体夹紧在窗口内**（8 px 边距）。拖到边界就停住，鼠标继续往外走时 `⠿` 不再跟；
  鼠标移出窗口后 mpv 不再发 `mouse-pos`，`⠿` 停在最后一次位置。好处是落位永远合法：面板不被裁、`⠿` 始终点得到，
  和 Windows 拖窗口的手感一致。**不做贴边吸附**。
- **记忆（定稿）**：写进 `source-markers-ui.json` 的 `panel_pos = {x, y}`（**窗口像素**），跨重启记住；
  每次加载、每次窗口尺寸变化都重新夹紧（`x ∈ [pad, w−panel_w−pad]`、`y ∈ [pad, h−total_h−pad]`，
  下界 > 上界时退化贴左上）⇒ 换分辨率不会跑丢，也不会因为归一化比例而"漂"。
- **与现有状态的互斥**：`panel_min`（最小化）状态下没有抓手、不可拖；关闭面板**不清**位置（与 `panel_min` 相反）；
  切到 Pr 控制栏时本位置不生效（控制栏是贴底布局）。
- **拖动中**：只保留 `⠿` 自己的 input section + `ESC`，其余按钮 section 临时 disable —— 避免拖动途中
  点到「打标记」直接执行。

## 四、播放跟随模式（`tl_play_follow`，r46 规划）

**Pr 的实测行为**（用户 2026-10-20 补充）：播放时区间**不动**，播放头可以跑出区间；**暂停时**才把区间平移，让播放头"尽量"回到居中（居中失败的情形与缩放的越界重排一致 —— 贴片头/片尾夹边界时只能偏侧）。

| 模式 | 播放中 | 暂停时 | 备注 |
|---|---|---|---|
| `off` | 不动 | 不动（播放头跑出去就画边缘箭头） | 当前行为 |
| `pr`（默认） | 不动 | 播放头在区间外 → 平移区间使其居中（夹 `[0,dur-span]`） | 与 Pr 一致 |
| `page` | 播放头到区间尾 → 区间平移一页（区间头 = 旧区间尾），播放头继续播 | 同 `page` | 用户提的"模式 1"：不让播放头跑出区间 |
| `center` | 始终平移区间让播放头居中 | 同 | 用户提的"模式 2"：像"锁在画面中央"，到片头/片尾会放跑 |

实现要点：`mp.observe_property('pause','bool',…)` 抓暂停时刻；播放中用 `time-pos` 观察器 + 节流（≥0.15 s 或跨帧）判断是否越过区间边界；一律复用 `tl_follow_playhead()` 的"保跨度 + 夹边界"逻辑，避免两套夹取规则打架。

**与 Pr 的差异（有意）**：Pr 的越界重排有 1 格延迟（第一格只挪出几像素、第二格才闪现），我们越界立即重排。
**实现状态（r46 第九轮）**：已按上表实现，配置项 `tl_play_follow` 默认 `pr`；`time-pos` 节流 0.15 s + `pause` 观察器；三处动作都有“没变化就不动”的守卫。
证据：pr 播放中区间恒 `10.000~20.000`，暂停后 `16.000~26.000`；page 20.5→`20.000~30.000`、9.5→`0.000~10.000`；center 27→`20.000~30.000`；off 不动；真实播放 13.000→15.733 区间不动，暂停在 15.800 → `13.300~18.300`。

### 概览条的构造（r46 第二十一轮，按 Pr 实测对齐）

Pr 的概览条由三部分组成，且三者的竖直范围**完全一致**：深色轨道（整片可滑动范围）、比轨道稍亮的灰矩形（当前可见范围）、两端圆形抓手。圆与轨道的几何关系是“轨道高 = 圆的直径、上下沿与圆相切”，灰矩形的左右两端落在两个圆的圆心。

实现口径（tl_metrics / render_timeline）：
- crv = floor(3.6*s+0.5) + 2 = 圆的**视觉**半径（poly 半径 + 外圈 1 + 描边 1）；
- ov_h = max(6, floor(7*s+0.5), 2*crv + 2)（概览行高，必须容得下整个圆）；
- ov_track_h = 2*crv（轨道高），亮段矩形高度也是 ov_track_h；
- 命中/边界一律用 crv（TL.geo.cr），不用 poly 半径，差 2 px 就是“圆顶那条边点不中”。

**可点区域必须覆盖整个圆**：mp.set_mouse_area 只覆盖画布正负 2 px 时，区间贴片头/片尾的圆有一半在区域外，mpv 不会把点击转给脚本（日志里只有“悬停”、没有“抓起”）。所以可点区域左右各放 2*hitr + 4，第 3 参写成右边界 xa + rw + 2*pad（写成“宽度”时不同 mpv 版本解释不一，右侧会被截断）。

### 概览条的外观口径（r46 第二十二轮）

- **齐平**：`crv = floor(3.6*s+0.5) + 1` 是圆的视觉半径（poly 半径 + 外圈 1 px），轨道高 `ov_track_h = 2*crv` 正好等于圆的视觉直径；取 cr+2 会让轨道比圆上下各凸 1 px。
- **颜色**：非激活轨道 `&H313131&`（Pr 标准）、可见范围 `&HD0D0D0&`（抓着中段时纯白）、抓手环 `&H8A8A8A&`（hover/抓取时纯白并放大 2 px）、环心 `&H1D1D1D&`（比轨道更暗，形成“空心”观感）。
- **空心环的画法**：同一坐标系下叠三层填充圆 —— 外圈暗（半径 r+1）、环体亮（半径 r）、环心暗（半径 r-ring），后画覆盖前画，不需要真正的“挖孔填充规则”。环厚 `ring = max(2, floor(cr*0.34+1))`。

### 拖圆的第二段：对称到贴边后退回单动（r46 第二十三轮）

- **进入/退出同动**：`in_win = pn and (|pn-0.5| <= lim or crossed_half)`，`lim` 进 0.02、出 0.05（`gr.sym` 为真时用 0.05）。`gr.sym_block` 只允许在 `not in_win` 时清除 —— 放在无条件 `else` 里会"同帧清锁"，让 `sp` 恒等于 `hi`、区间锁死。
- **触界判定**：`TL.bar_solve_center` 在目标够不到时返回 `hi`（钳位），上层不能只看 `sp <= hi`。要自己算 `q_at_hi = bar_geom(tph - hi/2, tph + hi/2)` 的目标端位置，与鼠标想要的 `want = target - gr.sym_off` 比较：抓右端 `q_at_hi <= want`、抓左端 `q_at_hi >= want` 即"对称已到极限"。
- **退出顺序**：`beyond_hi` 且当前跨度 < hi 时，本帧仍给 `sym = hi`（对称走到片头/片尾），下一帧才退回单动并上 `sym_block`。退回时锚点换成当前像素（`bar_geom(g.t0, g.t1)`），单动继续"贴边端钉住、另一跟手"。
- 与 Pr 的差别：Pr 实测放大是"1:1 跟手 + 约 37 px 固定偏移"、缩小有增益，本插件保留像素钉死 + 1:1，只对齐"贴边后退单动"这一档。

### 拖圆的第二段续：退单动要带上偏移（r46 第二十四轮）

- 对称阶段端点是「落位」出来的（`gr.sym_off` = 端点与鼠标之差），单动阶段端点是「跟手」出来的（端点 = 鼠标位置）。两段语义不同，直接切换等于把端点瞬移到鼠标处。
- 因此退单动的那一帧要记 `gr.mx_off = 当前端点 - target`，此后每次反解先 `target_eff += gr.mx_off`，让单动从「当前位置」继续跟手；一旦重新进同动就清掉 `gr.mx_off`（交给 `gr.sym_off`）。
- 转嫁（`kind_eff ~= gr.kind`）时不加偏移，因为转嫁的目标本来就按鼠标位移镜像算。
- 尚未消除的固有跳：进同动时跨度被 `min(span, hi)` 压到 `hi`（`hi = min(2·tph, 2·(dur−tph))`），播放头不在正中时会有零点几秒的收缩。

### 拖圆的第三段：转嫁粘滞（r46 第二十五轮）

- **转嫁**（抓的这端会让播放头远离中点时，把鼠标位移镜像到另一端）是**粘滞**的：一旦生效，保持到用户反向拖动（放大方向）为止。判据用每帧鼠标位移 `dpx`（`growing = 抓左端 dpx<-0.5 / 抓右端 dpx>0.5`），不看 `pn`。
- 为什么不能看 `pn`：转嫁的用途就是把被抓端推过播放头，`pn` 随后必然变 nil；若用它做保持条件，下一帧就撤销转嫁，`target_eff` 从镜像值回到鼠标绝对位置，区间整体瞬移（实测 +11.9 s）。
- **退出**：反向拖的第一帧把 `gr.l0/gr.r0` 换成当前区间的像素位置，并记 `gr.mx_off = 当前端像素 − target`，单动从当前位置继续；转嫁期间不加 `mx_off`（镜像值已经算好）。
- **取证**：`tl_dbg` 每帧一行，字段见速查表；排查这类问题时先看 `tr`/`te`/`pn` 三列的跳变，再决定改哪一段。

### 拖圆的第三段续：转嫁要以「触发那一刻」为基准（r46 第二十七轮）

转嫁（illegal -> kind_eff 镜像）本质是「把鼠标位移反向加到另一端」。位移必须相对**触发转嫁那一帧**取基准：

```
if illegal and not gr.trans then
    gr.mx_ref = mx
    gr.l_ref, gr.r_ref = TL.bar_geom(g.t0, g.t1, g.dur)
end
...
local m0n = ((gr.mx_ref or gr.mx0 or mx) - g.x0) / math.max(1, g.rw)
local lref = gr.l_ref or gr.l0
local rref = gr.r_ref or gr.r0
```

理由：抓起位置与该帧之间隔着整段单动缩放（用户实测 0.59 -> 0.39 归一化），用抓起位置当基准会把
这段位移一次性补到另一端上 ⇒ 端点瞬移。退出转嫁（growing）时清空这三个字段，并照旧用
`gr.l0/gr.r0 = TL.bar_geom(now)` + `gr.mx_off` 接续单动，保证退出也不跳。

## 十二、最小跨度与 Pr 的视图关系（r47 **已落地**，2026-10-22）

### 12.1 现状与根因

`tl_min_span()`（`source-marker-united-1.2.0-alpha-r46/mpv-player/portable_config/scripts/source-markers.lua:2603-2615`）把两个下限取 `math.max`：

- 帧下限：`fr / (get_fps() or 25)`，`tl_min_frames` 默认 15
- 像素下限：`dur * (tl_min_px / g.rw) ^ (1 / tl_ov_pow)`；40 px / 1055 px、pow 1.30 ⇒ **恒定 8.07% 片长**

像素下限的本意是"概览条上两环贴住就抓不住"，但它把「跨度下限」与「显示像素」绑死了：
1 h 素材最小 290 s（8714 帧），30 min 素材 145 s，而 30 s 素材只有 2.42 s —— 跨度下限随片长线性放大。

### 12.2 Pr 的实测（详见 `测量-Pr概览条与最小可视范围.md`）

| 素材 | 缩到最短时的可视范围 | 两环距/条宽 | 反推区间 |
|---|---|---|---|
| 30 s / 30 fps（900 帧） | **1.447 s = 43.4 帧** | 22 px / 1239 px = 1.78%（两环相切下限） | 0.77 帧（Pr 下限 = 1 帧） |
| 60 min / 23.976 fps（3610 s） | 6.17 s = 148 帧 | 0.0436 = 54 px | 6.4 帧 |

⇒ **Pr 能缩多细与片长无关**（1.45 s vs 6.17 s，片长差 120 倍）；mpv 是 `8% × 片长`（差 120 倍也跟着涨 120 倍）。

**概念澄清（早期汇报错过的坑）**：条上「两环距 / 条宽 = 区间跨度 / 可视范围」。两点法量出来的是**可视范围**，区间跨度要再乘 `w`。用户说的"缩到最短接近 30~50 帧"指的是可视范围。

### 12.3 改法（r47 三步，每步单独上机）

1. **跨度下限改固定帧**（✅ 已落地）：`tl_min_span()` 去掉像素项，`tl_min_frames` 默认改 **40**；新增 `tl_min_mode='frames'|'px'`（默认 `frames`，保留 `px` 作回退与对照）。
   影响点（五处，逐个确认）：`:2619` 夹取、`:2652` 与 `:2683` 缩放、`:2942` `bar_solve_center` 对称反解、`:3079-3132` 拖圆、`:3265` `wmin`。
2. **概览条显示下限**（✅ 已落地）：亮段与两环加最小可见宽度 `tl_ov_min_px`（默认 0 = `2*cr+2`，即两环刚好相切；Pr 实测下限 22 px 同口径），**只改绘制**，反解/命中仍用真实 `TL.bar_geom`。否则 1 h 素材的 40 f 亮段只有 0.0003 px，整段消失。
3. **概览条命中兜底**：两环间距 < 2×crv 时按"左半 = 左端、右半 = 右端"分辨；或维持现状（只拖中段平移）。主区（刻度区）本来就能拖边界，所以这条是可选的保险。

### 12.4 明确不做的事

- **不复刻 Pr 的环距曲线** `w = (V/dur)^b`（b 随素材变：60 min 是 0.478、30 s 是 1.33）。那是 Pr 滚动条的外观，不是我们要的语义；拟合它只会把 `tl_ov_pow` 又变成片长相关。
- **不引入"视图 ≠ 区间"的双坐标系**。mpv 的主区本来就映射区间 `[t0,t1]`，语义上等价于 Pr 的"可视范围"⇒ 只改下限即可达标。双坐标系会把 `bar_geom` / `bar_solve` / `bar_solve_px` / 拖圆五段 / 跟随逻辑全部拖下水，收益为零。
- 不为了"40 f 也要看得见"去动 `tl_ov_pow`、`tl_ov_k`。

### 12.7 条宽映射的最终口径（2026-10-22，r47 第六步）

**结论**：条宽指数不再手调，改为由「最小跨度要占多少像素」反推。

    w = u^pow,  u = span/dur
    pow = ln(W/rw) / ln(minspan/dur)
    W = tl_ov_min_px = 26 px（含两环；两环之间横条 13 px = 1 个圆径）
    rw = 当前画布宽, minspan = tl_min_span()（r47 起 = tl_min_frames/fps）

- 为什么 26 px：Pr 最小可点区间是 31 px = 两个 10 px 圆 + 11 px 横条（≈1 圆径）；我方环径 13 px，
  等比 ⇒ 环心距 26 px、横条 13 px。
- 为什么反推而不是调参：直接抬高视觉下限会「撑开」——把环画到真实映射里不存在的位置，拖动必然漂
  （第五步修的就是这个）。反推让**最小档本身就是真实映射**，撑开逻辑退化为纯兜底。
- 与 Pr 实测的一致性（60 min 素材，归一化宽 w）：u=0.7755→0.8878（Pr 0.8878）、0.3065→0.5745（0.5714）、
  0.2287→0.5016（0.4976）、0.0190→0.1566（0.1457）、0.00171→0.0507（0.0436）。
  即"按最小跨度反推"几乎复现了 Pr 的整条曲线，无需再拟合 b。
- 副作用：pow 依赖 rw ⇒ 窗口变宽/变窄时整条曲线重算（最小档恒 26 px，Pr 亦随窗口变）。
- 接口：TL.bar_pow(dur) 是唯一入口，绘制（bar_geom）、反解（bar_solve / bar_solve_px / tl_ov_time）、
  拖动下限（wmin）全部经它；显式 tl_ov_pow=数字 仍可固定对照。

### 12.8 圆环的几何（r47 第七步定稿）

    内层高（亮段）= 2*cr = 12 px     （cr = max(3, floor(3.6*s+0.5))，s 为 OSD 缩放）
    环半径 = cr + 1 = 7  ⇒ 环径 14 px（比内层高 2 px，"顶出"横条 1 px）
    环厚 = 单边 3 px，暗心 8 px
    环心距 = tl_ov_min_px = 27 px    ⇒ 中间横条 = 27 - 14 = 13 px

- **环必须比内层高 2 px**：若环径 == 内层高（相切），圆的四个肩角与矩形边缘之间必然留下月牙形暗区
  （内层 #141414），16 倍放大后就是"发黑的一点点"。顶出 1 px 后月牙被环本身吃掉。
- **圆环用 48 段多边形**：`circle_pts` 默认 16 段，半径 6 时弦高差 ≈0.12 px，放大后成锯齿；
  48 段差 ≈0.013 px，抗锯齿过渡自然。图标仍用 16 段（不影响）。
- **不靠加厚解决"发毛"**：试过单边 4 px（暗心 5 px），放大后像实心圆盘，离 Pr 的细环更远。

### 12.9 模式切换的"偏移"必须收敛（r47 第八步）

    退同动那一帧：gr.mx_off = 端点像素 − 鼠标位置     （目的：切模式那帧端点不跳）
    此后每帧：target_eff = target + mx_off

- **定值偏移不能一直加**：鼠标拖到条尾时 target = 1，端点只到 `1 − |mx_off|`，永远吃不满 ⇒
  右圆在 28.787 s 锁死（1 h 素材、偏移 0.046）。用户体感是"控制环锁死了"，而 Pr 那里是"鼠标贴到屏幕挪不动"。
- **口径**：切换瞬间的偏移只用于那一帧的对齐，之后每帧减半、`|off| < 0.002` 清空（4 帧内 < 3 px）。
- **例外**：转嫁退出时记的 `gr.mx_off` 是"鼠标位移 → 另一端位移"的**基准**，必须一直带着，不能衰减
  ⇒ 用 `gr.mx_off_decay` 标记区分两种来源。

### 12.10 贴边式子只对"钉死那一端"生效（r47 第九步）

    bar_solve_px(dur, anchor, target, side, minw, edge)
      side='right'  抓右端 ⇒ 钉死左端 ⇒ 只有左端贴 0 才走 head 式子
      side='left'   抓左端 ⇒ 钉死右端 ⇒ 只有右端贴 dur 才走 tail 式子

- **`edge` 是抓取那一刻的快照，不能脱离 `side` 使用**：抓左端时区间贴片头（`t0=0` ⇒ `edge='head'`）
  是常态，若照用 head 式子就会把"跟手的左端"拉回 0、宽度取 `|target − anchor|`，
  右端因此随鼠标乱跳（用户 m04610 看到的"右圆轨迹不可预测"）。
- **判据**：绘制时贴边的那一端 = **被钉死**的那一端（`bar_geom` 的 at_head/at_tail），
  反解必须与它同端，而"被钉死的那一端"由 `side` 决定，不由抓取时的区间位置决定。


## 十三、r47 定稿：最小跨度与概览条口径（2026-10-22）

### 13.1 最小跨度：与片长无关

```
tl_min_span()  =  max( 帧下限, 像素下限 )
  帧下限   = tl_min_frames / fps                     -- 默认 40 帧，与片长无关
  像素下限 = dur * (tl_min_px / rw) ^ (1/pow)        -- 只在 tl_min_mode='px' 时启用（旧口径，恒定 ~8% 片长）
```

- 默认 `tl_min_mode='frames'`、`tl_min_frames=40`。1 小时素材最小跨度 **290 s → 1.668 s**。
- 旧口径（`tl_min_mode=px`）保留用于对照：`tl_min_px=40` 时恒等于 8.07% 片长（1 h → 290 s）。

### 13.2 概览条宽度：指数是"反推"出来的，不是拟合常数

```
w = u ^ pow            u = 跨度 / 片长，w = 亮段宽 / 条宽
pow = ln(W / rw) / ln(minspan / dur)
      W = tl_ov_min_px（默认 27 px，= 两环 27 环心距，横条 13 px）
      rw = 概览条可用宽度，minspan = tl_min_span()
```

- 反推保证「最小跨度 ⇒ 亮段恰好 W 像素」，因此**最小档是真实映射，不需要撑开**（撑开会导致拖动时圆与鼠标错位 = 漂移）。
- 反推不成立（W/rw ≥ 1、minspan ≥ dur、片长异常）时回退 log10(片长) 插值：
  30 s → 1.33，60 min → 0.478，夹在 `[0.42, 1.40]`。
- 对照 Pr 实测（60 min 五档，w = 亮段/条宽）：我方 0.8878 / 0.5745 / 0.5016 / 0.1566 / 0.0507；
  Pr 0.8878 / 0.5714 / 0.4976 / 0.1457 / 0.0436。

### 13.3 反解三件套（必须与绘制同源，否则漂移）

| 函数 | 用途 | 关键点 |
|---|---|---|
| `TL.bar_geom(t0, t1, dur)` | 绘制 + 命中 | 贴片头钉 `(0, w)`、贴片尾钉 `(1-w, 1)`；中间走 `c = 0.5 + (mid-0.5)/k(u)` |
| `TL.bar_solve_px(dur, anchor, target, side, minw, edge)` | 像素钉死反解 | `edge` + `side` 必须同时匹配才走贴边式子；宽度越界按整片收口 |
| `TL.bar_solve(dur, fixed, target, side)` | 时间域二分 | 越界自然收敛到端点，不会返回 nil |

- `side=='right'` 才认 `edge=='head'`；`side=='left'` 才认 `edge=='tail'`。早期不分抓哪端都看抓取时的 edge ⇒ 抓左端时被强行走 head，区间跳 `[0,10]`。
- `bar_solve_px` 里 `w > 1` 按整片处理（不能 `return nil`）：调用方拿不到 `pa` 会回落旧式子 ⇒ 鼠标拖出条外就锁死。

### 13.5 拖动语义（r47 最终版）

- **相对位移**：`d = (target - m0) * C * dur`，`C = 0.6`（鼠标走过 1 个条宽，时间上走 0.6 个片长）。
- **连续量用端点位置**，不用跨度：对称段右端 `= tph + sp/2`，撞边段右端 `= sp`。
  用跨度会让撞边瞬间速度翻倍（0.60 → 1.20）。
- 速度观测值：单动 0.88~0.95、同动 0.60、撞边 0.60（**台阶保留**，用户 m04789 决策）。
- 鼠标位置钳 `[-0.5, 1.5]`（条内外各留半条宽），越界由反解按整片/最小收口。
- 触发条件：`|p - 0.5| <= 0.02` 进入同动、`> 0.05` 退出（迟滞）；触界退单动。

### R48-1 补记：字体度量按截图像素校准（2026-10-24，用户 m06041 / m06132）

**现象**：上一版把系数从 0.58 改成 0.5（"1 个显示单位 = 0.5 em" 的理论值）后，用户仍反馈「每个按钮的文字右端还有如此多的空余」，并给出裁剪图（一个「导出标记（另存为迭代）」按钮，文字只占左侧约 70%）。

**做法（先造尺子，不猜）**：新增 `tools/measure-buttons.py` —— 扫按钮块、按边行切出每个按钮矩形、块内求文字包围盒，输出每个按钮的 `L/R`（文字左侧余量 / 右侧余量）。

- 大坑：面板是半透明（背景 alpha `25`、按钮 alpha `35`），叠在视频上颜色随画面变 ⇒ 同一个按钮在同一行里既是 `(45,45,45)` 又是 `(51,34,32)`，按颜色切分全乱。**必须在纯黑画面上量**：用 `reference/ref-CFR-23976-60min.mp4`（用户 m06264 提示：除 0/10/15/30/45/60 min 外都是纯黑）加 `--start=20 --pause=yes`，此时面板底 `(18,18,18)`、按钮底 `(40..44)` 恒定。
- 另一坑：`gui_window_shot` 的 `image_px` **含标题栏**，客户区要往下挪一个标题栏高度才能对上；而标题栏高度随 DPI 缩放变（2560×1600 / dpi 1.75 时量到 52 px，1280×800 时约 39 px）。别记常数，用 `tools\col-runs.py <png> <x> <y0> <y1>` 在某列上扫一遍，标题栏与面板底色的分界一眼就看见。

**实测（两个字号交叉验证）**：

| 窗口 | 字号 size | pad | bh | 「标记列表」8 单位 | 「导出标记（另存为迭代）」22 单位 | 文字左右余量 |
|---|---|---|---|---|---|---|
| 1165×651 | 17 | 6 | 29 | 66 px | 149 px | L 7~9 / R 5~6 |
| 2400×1300 | 26 | 10 | 46 | 102 px | 228 px | L 11~12 / R 9~10 |

由实测反推的 em 系数（**不是理论值**）：汉字 0.77 em/字、ASCII 0.62 em、空格 0.25 em、全角标点（UTF-8 前缀 EF BC / E3 80）0.5 em。
原来的 `0.5` 系数等于假设「汉字 = 1.0 em」，高估 30% —— 这就是"右边总有空余"的根因；而 `visual_width` 的"单位"口径对 ASCII 反而低估（"OSD 样式"那条文字曾顶到按钮右边缘 R=0）。

**改法**：新增 `UI.label_px(s, size)`（挂在 `UI` 表上——主 chunk 已到 200 个 local 上限），按字符类别累加像素；`title_w`（`:1960`、缩字号循环 `:2039`）与 `place()` 的 `tw`（`:1975`）三处都改用它。文字仍按 `x + (bw-tw)/2` 居中。

**结果**：1165×651 面板宽 **1030 → 851**（横向可动区间 56 → 302 px）；2400×1300 **1593 → 1304**；两个字号下所有按钮的左右余量都对称在 pad 附近，「切换 OSD 样式」的 R 从 0 变成 7。

**未做**：控制栏（`:2275` 0.58）、时间码（`:2437`/`:2550`/`:2579` 0.55）、帮助面板（`:4073` 0.72）仍是估算系数，同样高估 20~40%，等用户提到再按同一把尺子量。

### R48-3 落地记录：鼠标跟随 + 两处视觉口径（2026-10-24）

**跟随**（`on_mouse_pos` 开头）

- 抓起时记「面板左上角 相对 鼠标」的偏移 `UI.panel_drag_off = {dx, dy}`（`mp.get_property_native('mouse-pos')` 减 `UI.panel_geom`）；按住期间**偏移不变**，`UI.panel_pos = {mx - dx, my - dy}`，⠿ 才会稳稳钉在鼠标下。用 `Alt+F3` 抓起时鼠标不在抓手上，同样按当时鼠标位置起算，不会跳一下。

**补丁：鼠标移出窗口就自动放下**（用户 m07069：「鼠标移出窗口再移回来会出现瞬移 to follow，可以在鼠标移出窗口时直接放下 / 回到原有位置（可选，默认前者）」）

**未做**：贴边吸附（定稿不做）；拖动时面板半透明跟随鼠标变淡；`panel_min` 下拖动。
