## 1. 定性框架：Pr 源监视器的时间轴分三层

| 层                | 是什么                                                | 性质                                   | 怎么测                                   |
| ----------------- | ----------------------------------------------------- | -------------------------------------- | ---------------------------------------- |
| **L1 轨道本体**   | 时间轴那条带子（缩略图/波形），两端 = 可见区间起止    | **等时 / 线性**：帧 → 像素是常数 `pxF` | 量 `pxF`（T1），后面所有换算靠它         |
| **L2 概览控制条** | 底部 `⚪━━⚪`：整条 = **整片**，亮段 = **当前可见区间** | **非线性嫌疑就在这层**                 | 量"亮段宽 / 整条宽"（T2，纯读不拖）      |
| **L3 缩放状态**   | 当前缩放级别（`=` 每次 ×2）                           | 级别 = 整片 ÷ 2ⁿ                       | 记级别 n 与 `pxF`、亮段宽的关系（T2/T3） |

**关键换算**（因为 L1 线性，所以成立）：
`可见起点(帧) = P - (x_P - xL) / pxF`，`可见终点(帧) = P + (xR - x_P) / pxF`
（`P` = 播放头处帧号，从素材画面直接读；`x_P` = 播放头竖线像素 x；`xL`/`xR` = 轨道左右边界）

**L2 的映射**记作 `亮段比例 = g(区间比例 u)`，`u = 可见区间 / 整片`（0..1，`g(1)=1`）。

## 3. 测量项（每项都是"截图 + 点两下"）

### T1 量 `pxF`（一次就够，换算基础）

1. 播放头停在整秒（素材顶部 `xx:xx:00`）//1s0f → 截图 → 点播放头竖线，记 `x_P`
2. 按 → 十次（+10 帧）→ 再截图 → 点播放头，记 `x_P2` ⇒ `pxF = (x_P2 - x_P) / 10`
3. 顺手量轨道左右边界 `xL`、`xR`（时间轴带子两端），之后一直用
4. Pr 若有"吸附到整秒"请关掉（开着要备注）

### T2 量概览条映射 `g(u)`（**核心，纯读不拖**）

1. 缩到"整片"（`\`）→ 截图 → 量**整条宽** `W_bar` 与**亮段宽** `S_0`（此时 `u=1`）
2. 按 `=` 一次（`u=0.5`）→ 截图 → 量 `S_1` ⇒ `g(0.5) = S_1 / W_bar`
3. 再按 `=`（`u=0.25、1/8、1/16`）→ 各截一张 → 量 `S_n`
4. 把 `(u, S_n/W_bar)` 报我（或看 `S_{n+1}/S_n` 是否恒定）—— 4~5 张截图就够

> 这就是你这轮"亮段 1/3~1/2"的**精确定量版**：只截图 + 点两下，不用拖任何东西。

### T3 量锚点模型（缩放时画面绕谁伸缩）

1. 中间级别，播放头放到画面**左边 1/4** //3s:22f n112 （读 `P`）→ 截图 → 量 `x_P`
2. 按 `=` 一次 → 截图 → 量 `x_P'`
3. 判读：
   - `x_P` 不变 ⇒ **锚点 = 播放头**
   - `x_P` 往中间走一段然后停住 ⇒ "先移到中心再钉住"（你描述的感觉）
   - `x_P` 每格位移与 `(x_P - 中心)` 成比例 ⇒ 指数拉力（我拟合系数）
4. 播放头放**右边 1/4** 再重复一次（看是否对称）

### T4 抓手 / 中间拖动（可选，最后做）

拖动前后各截一张：量**亮段两端**与**圆的像素 x** ⇒ 得该位置的 `dt/dx`（抓手灵敏度）。片头/中间/片尾各一次。

### T5 边界与吸附（可选）

最小/最大级别的亮段宽、两端拖到底的行为、播放头能否停在帧中间。

## 6. 数据结论（2026-10-14 实测，我用 `tools\fit-pr-model.py` 回归）

### 6.1 T2：概览条是**幂律**，指数 p ≈ 1.291

你量的亮段宽（整条 `W_bar = 2506`）：

| u = 区间/整片 | 亮段宽 | 比例 | 本次/上次 | p = -log2(比例)/log2(u) |
|---|---|---|---|---|
| 1（整片） | 2506 | 1.0000 | — | — |
| 1/2 | 1028 | 0.4102 | 0.4102 | **1.2855** |
| 1/4 | 420 | 0.1676 | 0.4086 | **1.2885** |
| 1/8 | 171 | 0.0682 | 0.4071 | **1.2911** |
| 1/16 | 68 | 0.0271 | 0.3977 | **1.3009** |

- **每按一次 `=`（区间减半），亮段比例常数 ×0.408** ⇒ 严格的幂律 `亮段宽 ∝ u^p`，**p = 1.291**（四个独立估计 1.286~1.301，非常稳）。
- 用 p=1.2914 反算：`540.6 / 221.4 / 90.4 / 36.5` px，与你实测 `1028/420/171/68`（按 2506 缩放后 = `541/221/90/36`）**逐项吻合到 1 px**。
- ⇒ 我之前做的 `sqrt`（p=0.5）**方向反了**：它把小区间画得**更长**，Pr 是画得**更短**。
  "越往右条越短 / 挪条几乎不动"那套怪手感，就是这个反方向造成的，不是 bug。

### 6.2 T1：一帧多少像素（换算用）

`pxF = (135-107)/10 = 2.8 px/帧`（整片级别）；轨道边界 `xL = 24, xR = 2525`（轨道宽 2501 px）。
⇒ 整片级别可见范围 ≈ 2501/2.8 = 893 帧 ≈ 900 帧 = 整片 ✓（与 `\` 适合窗口一致）。

### 6.3 T3：缩放锚点 = **每 ×2 一步，把"离中心的偏移"乘 2/3**

把播放头在轨道里的相对位置算出来（`p = (x-xL)/(xR-xL)`）：

| 位置 | 缩放前 p | 按一次 `=` 后 p' | 离中心偏移的倍率 k |
|---|---|---|---|
| 左 1/4 | 0.1242 | 0.2487 | **0.6688** |
| 右 1/4 | 0.8757 | 0.7511 | **0.6684** |

- 两边**完全对称**，k ≈ **0.6686 ≈ 2/3** ⇒ Pr 的规则极可能就是 **k = 2/3**（设计上取整）。
- 换算成我代码里的参数：`p' = 0.5 + (p-0.5)·(1/倍率)^pull`，倍率=2 时 `2^-pull = 2/3` ⇒ **pull = -log2(2/3) = 0.585**。
- ⇒ 你上次说"手感诡异"的原因也清楚了：我当时默认的 `pull = 4`（一步就把偏移收掉 94%），比 Pr 强了约 7 倍。

**离线复算**（同一台机器上跑探针）：`u = 1/2, 1/4, 1/8, 1/16` 时亮段 = `541 / 221 / 90 / 37` px（与你的 Pr 数据一致）；

### 6.5 还剩**一个**没定的问题（T2b，两张截图就能定）

T2 那五张图里可见范围**都是从 00:00 开始的**，所以它只能定"亮段宽 = u^p"，不能区分下面两种结构：

- **A. 整条是"时间的位置图"**（我现在实现的）：`屏幕比例 = (t/整片)^1.29`，亮段 = `(t1/D)^p - (t0/D)^p`。
  ⇒ 预测：**同样大小的区间，靠片尾时亮段更宽**（u=1/2 在 [15,30] 时应为 `1-0.5^1.29 = 0.592`，而在 [0,15] 是 0.408）。
- **B. 位置线性、只有亮段宽度是非线性**：`左端 x = t0/D`，`亮段宽 = u^1.29 · 条宽`。
  ⇒ 预测：亮段宽只跟 u 有关，**同样大小时在片头/片尾一样宽**。

**T2b（30 秒）**：同一缩放级别（区间 = 15 s）拍两张——
① 范围在片头（00:00~15:00）② 范围在片尾（15:00~30:00），各量亮段宽与两端圆的位置。
差得明显（0.59 vs 0.41，约 1.4 倍）⇒ 是 A；几乎一样 ⇒ 是 B。

## 7. 下一轮测量方案（NS1–NS4）：缩放可逆性 / 非边界位置 / 概览条结构

### 7.0 已知 vs 未知（先说清为什么还要测）

- **已知**：`=` 恒定 ×2（但那是在**播放头 00:00、左端被夹住**时测的）；概览亮段 ∝ `u^1.29`（五张图的区间**都从 00:00 起**）；
  放大时"离中心偏移 ×2/3"（T3，且当时区间 = 整片）。
- **未知**（你这轮发现的）：① **缩小**的规则（我按"对称"假定的，从没测过）；② **非边界位置**（播放头 10 s）时区间怎么变；
  ③ 概览条到底是"位置图 A"还是"位置线性 + 宽度非线性 B"；④ 区间撞到片头/片尾时怎么夹。

### 7.1 统一做法（最省你的事）

1. 播放头停在目标位置（用素材画面确认帧号）。
2. 每一步操作后，**再多按 `→` 十下**截一张、`←` 十下回原位再截一张 —— 两张一对：
   我用"同一条时间轴上播放头竖线位移 10 帧 = 多少像素"算出这一级的 `pxF`，再把图上量到的 x 换成**精确时间**。
3. 截图丢进 `reference\measure\`（命名带步骤号，例如 `NS1-01a.png` / `NS1-01b.png`），**我来量、来算、来画表**，你只管点。

### 7.2 NS1 非边界位置的缩放（回答"10 s00f 处两边区间不一致"）

- 播放头 = **10 s 00 f**（画面顶部 `00:10:00`）。从**整片**级别开始。
- `=` ×4：每步一对截图；再 `-` ×4：每步一对截图。
- 我会算出每步的：精确区间 `[起, 止]`、跨度、`pxF`、`p`（播放头在区间里的相对位置）。
- **要回答**：`=` 时跨度是不是**正好减半**（不是的话倍率是多少）；`-` 时是不是**正好加倍**；`-` 回到的状态与 `=` 之前是否**逐帧一致**。
- 再用播放头 = **20 s 00 f** 重复一遍（看规律是否随位置变）。

### 7.3 NS2 可逆性（回答"按 `-` 区间向右漂移"）

**先对齐术语**：本项只测"**可逆性**"——`=` 之后再 `-`，能否回到原处。
它**不涉及** `←/→` 平移（那是 NS5，见 §7.7）。

已覆盖的部分不必重做：

| 播放头 | 结论来源 | 结论 |
|---|---|---|
| 10 s（非边界） | NS1：`=`×4 后 `-`×4 | 回程与 S0 逐像素一致 |
| 3 s（u=1/2 被钳到 0） | NS4 A 轮 | 回程 `-`1…`-`3 与 `=`3…`=`1 相同，`-`4 回到整片 |
| **0 s（极端边界）** | **待测 —— 本项唯一剩余** | — |

做法：播放头 = **0 s**，从整片开始 `=` ×6（每步记 `x_P / cL / cR`），再 `-` ×6（同样记），
每步一张截图且**概览条要截进来**。

判据三条：
1. `=` 时区间左端是否**钉在 0**（`[0,15]`、`[0,7.5]`…），而不是跟着播放头缩；
2. `-` 回程每一行是否与对应 `=` 行**完全一致**；
3. 最后一步是否回到整片（`x_P` 归一化 = 0）。

> 我这边同条件的预期：`[0,15] → [0,7.5] → [0,3.75] → …`，回程逐级还原，末步 `[0,30]`。
> 旧版在播放头 0.023 s 处会走成 `[0.023, 1.023]`（差 0.7 帧），已修，正要用这一格确认。

### 7.4 NS3 概览条结构：A 还是 B（决定"位置图"还是"中心线性 + 宽度幂律"）

- 先做 **15 s** 的区间（整片一半），用拖动/`Alt+滚轮` 把它放到三个位置：① 片头 `[0,15]` ② 中间 `[7.5,22.5]` ③ 片尾 `[15,30]`，各截一张。
- 再做 **7.5 s** 的区间，同样三个位置各截一张。
- 每张**只量概览条**：整条左右端、两个圆的 x、亮段两端。
- **我会判读**：
  1. 三个位置的亮段宽（占整条百分比）是否相同 ⇒ **相同 = B**（宽度只看区间大小），不同 = A（位置图）；
  2. 若为 B，再验证 `(cL+cR)/2` 是否等于 `条中心 + (区间中心/整片)×条宽` ⇒ 确认"**中心线性 + 宽度 u^p**"这一种具体形式。

### 7.8 NS6 滚轮分区（用户实测修正：时间轴 ≠ 控制条）

**先说为什么改口径**：原以为“鼠标缩放”是一件事，实测不是——Pr 里滚轮按**区域**分工：

- 只有指针落在**下面的控制条**（整条：圆圈横条 + 滑轨）内滚轮 → **区间变小 / 变大**。

所以我们 mpv 侧现在这套“全窗口滚轮 = 缩放”**与 Pr 不一致，要改成分区**（改法见本节末尾）。

| 11A 时间轴滚轮 | 指针在轨道中间，向上/向下各滚 1 格、连续 3 格、贴边再滚 | 帧号差是否恰为 ±1；`cL/cR` 是否跟着滚（区间跟随 vs 只动播放头）；贴边时区间被推走还是播放头停住 |

| 11C 横向滚动与拖动 | 控制条上左右滑、拖中间 100 px、拖左/右圆各 50 px | 平移 / 改范围分别对应哪种手势 |

### 8.8 NS3 结果（2026-10-15）：概览条确认是 **B**，指数 p ≈ 1.30；位置映射还需一组数据

**原始数据**（`bL=36`、`bR=2524.5` 取自整片状态的两个圆心；圆直径 16~18 px，只用圆心距，几何上会自然抵消）：

| 级别 | 状态 | cL | cR | 亮段宽（px） | 占比 `(cR−cL)/(bR−bL)` |
|---|---|---|---|---|---|
| n=1（u=1/2） | ① 贴死最左 | 36 | 1046 | **1010** | 0.40587 |
| n=1 | ② 贴死最右 | 1514.5 | 2524.5 | **1010** | 0.40587 |
| n=1 | ③ 大致中间 | 808.5 | 1818.5 | **1010** | 0.40587 |
| n=2（u=1/4） | ① 贴死最左 | 36 | 438.5 | **402.5** | 0.16177 |
| n=2 | ② 贴死最右 | 2122 | 2524.5 | **402.5** | 0.16177 |
| n=2 | ③ 大致中间 | 1073 | 1475.5 | **402.5** | 0.16177 |

### 结论一：确认 **B**（宽度只看区间大小，与位置无关）

同一级别下三个位置（贴左/中间/贴右）亮段宽度**逐像素相同**（1010 与 402.5）。

⇒ 概览条**不是**"时间→位置"的单调映射（那会让同样大小的区间在片头/片尾画出不同宽度）。宽度只由 `u` 决定。

### 结论二：宽度映射仍是幂律，`p ≈ 1.30`

`亮段占比 = u^p`：
- n=1：`p = ln(0.40587)/ln(0.5) = 1.3007`
- n=2：`p = ln(0.16177)/ln(0.25) = 1.3138`

与上一轮 T2 的 1.291 合在一起 → **p = 1.29 ~ 1.31**，现在代码里的 `tl_ov_pow = 1.29` 可以直接沿用（若要更贴中值可设 1.30）。

> 口径说明：若 bL/bR 改用「圆外缘」（27 / 2533.5），占比变成 0.4029 / 0.1606，p = 1.312 / 1.323 —— 差异 0.5%，不影响结论。

### 结论三：端点会被**夹取**，所以贴边状态不能用来反推位置映射

- 贴左时亮段左端恰好 = `bL`（36），贴右时右端恰好 = `bR`（2524.5）；
- 而且贴左时的亮段中心 = 宽 ÷ 2（n=1: 0.2029 = 0.40587/2；n=2: 0.0809 = 0.16177/2）——
  这正是"亮段被夹进 [0, W] 之后"的必然结果，**不是**位置映射的证据。

⇒ 三个状态里两个是夹取结果、一个是"大致中间"（n=1 中心 0.5135、n=2 中心 0.4976，只能确定 `g(0.5) ≈ 0.5`）。
**位置映射 `g(t)` 仍未知**，需要 NS3b。

| # | 播放头（时间码） | 帧号 | t_center/D | cL | cR |

**我会怎么判**

### 8.10 NS3b 结果与实现（2026-10-15）：概览条映射定案 = **宽度 `u^1.30` + 中心线性放大 `k=1.1886`**

**五点拟合**（`bL=36`、`bR=2524.5`、`W=2488.5`，每次从整片按一次 `=`，区间中心 = 播放头）：

| # | c = t_center/D | 亮段宽 | 中心归一化 f | f − c | k = (f−½)/(c−½) |
|---|---|---|---|---|---|
| 1 | 0.2667 | 1008.5 | 0.2229 | −0.0437 | 1.1875 |
| 2 | 0.3667 | 1010.0 | 0.3416 | −0.0251 | 1.1882 |
| 3 | 0.5000 | 1009.5 | 0.5000 | 0.0000 | — |
| 4 | 0.6333 | 1010.5 | 0.6587 | +0.0254 | 1.1905 |
| 5 | 0.7333 | 1009.5 | 0.7773 | +0.0439 | 1.1883 |

- 宽度**五点全同**（1009.6 ± 1 px）⇒ B 再次确认；占比 0.40571 ⇒ `p = 1.3015`。
- 中心偏差关于 0.5 **严格反对称**，且 `k = 1.1886`（五个点离散 < 0.3%）⇒ **中心是线性映射，斜率 1.1886**。
- 用 `k=1.1883 / p=1.30` 反算五点的亮段两端，与实测相差 **< 1.6 px**（见 `tools\analyze-ns3b.py`）。

**模型（已实现）**

```
u = (t1 - t0) / D                     -- 区间占比
c = ((t0 + t1) / 2) / D               -- 区间中心占比
w = u ^ tl_ov_pow                     -- 宽（只看大小）
xc = 0.5 + (c - 0.5) * tl_ov_k        -- 中心（线性，斜率 > 1）
left = xc - w/2 , right = xc + w/2    -- 最后夹到 [0,1]
```

## 9. NS6 11A 定论（2026-10-20）：时间轴滚轮 = 单帧步进，越界才翻区间

数据见《测量工作表-NS1NS4.md》§11A（30 s / 900 帧素材，区间 `[2.5, 17.5]` s = 帧 75–525，播放头 300 帧）：

| 操作 | 播放头帧 | x_P | cL | cR | 亮段宽 |
|---|---|---|---|---|---|
| 起点 | 300 | 1274.5 | 282.5 | 1292.5 | 1010 |
| 向上 1 格 | 299 | 1269 | 282.5 | 1292.5 | 1010 |
| 再向上 1 格 | 298 | 1263.5 | 282.5 | 1292.5 | 1010 |
| 向下 3 格 | 301 | 1279.5 | 282.5 | 1292.5 | 1010 |
| 播放头停区间**左端**（75 帧），向上 2 格 | 74 | 434.5 | 36 | 1046 | 1010 |
| 播放头停区间**右端**（525 帧），向下 2 格 | 526 | 1274.5 | 1025 | 2035 | 1010 |

**四条结论**：

1. **一格 = 一帧**，线性无加速（300→299→298；298 向下 3 格 = 301）；方向**向上 = 后退**。
2. **区间不跟随**：前四行 `cL/cR` 逐像素不变 ⇒ 播放头在区间内自由移动，视图不动。
3. **越界才翻区间**：后两行 `cL/cR` 位置变了、但**亮段宽恒 1010**（u=0.5 不变）⇒ 平移、保跨度。
4. 越界后 Pr 想把播放头**居中**：右端那次成功（`x_P`=1274.5=轨道中心），左端那次因贴片头夹边界只能偏左（`x_P`=434.5）。

自洽校验：`x_P` 每帧位移 5.5 px ↔ 轨道 2501 px ÷ 450 帧 = 5.56 px/帧（0.5 px 量化）✓；亮段宽 1010/2501 = 0.404 ≈ 0.5^1.30 ✓（与 NS3 的 `u^1.30` 同一族）。

**Pr 的 1 格延迟**：第一格只把播放头挪出边界几个像素、控制条不动，**第二格**才“闪现”重排 —— 这是实现副作用，我们**有意不模仿**，改成越界立即重排（可预测）。

**实现**（`mpv-player/portable_config/scripts/source-markers.lua`）：新增 `tl_follow_playhead()`（越界时 `n0 = t - span/2` 再夹 `[0, dur-span]`），`tl_wheel_frame()` 改成直接 `set time-pos` 并调用它。

**验证**（`_tmp/tl23.log`）：左端 2.500 s 向上 1 格 → 播放头 **74 帧**、区间 `0.000~15.000`；右端 17.500 s 向下 1 格 → 播放头 **526 帧**、区间 `10.033~25.033` —— 与 Pr 实测的 74 / 526 **逐帧相同**。
#### NS6 11B 定论（滚轮缩放，2026-10-20 二轮实测）

- **锚点**：Pr 以**视图中心**为轴（缩放态实测：中心 787→788.5，±1.5 px；"指针锚点"预测偏 5 px、"左端锚点"预测左端不动，均不符）。因为该状态播放头正好居中，也可描述为"播放头锚点"。
- **与光标位置无关**：指针在控制条 1/4 与 3/4 处，跨度比一致。
- **步长**：缩放态 **0.4%/格**、`Shift` **1.5%/格**（≈10 倍）；整片态读数 0.15%/格是概览条非线性映射造成的，非步长差异。
