
# Pr 概览条：实测、反推数学、mpv 实现与复盘

> **这份文档是什么**：r46/r47 里耗时最多、价值最高的一段 —— 把 Premiere 源监视器的"缩放条（概览条）"
> 用像素级实测反推出数学模型，再在 mpv 的 Lua OSD 里等价实现。
> 写于 2026-10-22（r47 收束），数据来自三轮真机测量，代码位置对应 `source-markers.lua`（r47）。
>
> **谁该读**：要改时间轴外观/手感的人、要重测 Pr 的人、想知道"当年为什么这么拟合"的人。

## 0. 结论速览（先看这 9 条）

1. Pr 的概览条把"当前可见区间 `[t0,t1]`"画成一条**亮段**，两端各一个圆环（抓手）。
2. 亮段宽度 `w` 只看**区间/整片之比** `u`，与区间在时间轴上的位置**无关**（同 u 下贴左/贴右/居中宽度完全相同，实测差 0 px）。
3. 宽度关系是幂律：`w = u ^ p`。**p 不是常数，随片长变化**：22 秒级短片 p≈1.30，60 分钟素材 p≈0.478。
4. 亮段**中心** `xc` 在短片上与区间中心时间**完全线性**（5 点残差 ≤0.6 px）；长片上会**向 0.5 聚集**，拟合为 `xc = 0.5 + (c/dur − 0.5)·k(u)`，`k(u) = 1 − 0.65·u^0.45`。
5. 贴片头/片尾时，Pr **钉死那一端**（`l=0,w` 或 `1−w,1`），不用中心公式 —— 这也是"贴边时圆环不能漂"的根源。
6. Pr 有**最小跨度下限**（≈45–50 帧），低于它再按缩小只缩 0.72 倍、且回程会跳级（Pr 自己不自洽）。
7. mpv 侧最终实现：`w = u^pow`、`pow` **反推**自 `(tl_ov_min_px, minspan, dur)`，保证"最小跨度恰好在条上占 27 px"。
8. 拖动用**像素钉死反解**（`bar_solve_px`）：抓哪端就钉另一端，解出的两端与绘制同源，所以不漂。
9. **复盘结论（见 §6）**：NS1–NS4 的实测数据是对的、也确实被采纳了；出问题的是"用一个片长下的常数去套所有片长"。

## 1. 数据结构：条上有哪几个量

Pr 源监视器的概览条（1280×800 时约 `x=20..1260`，`y=693`；2560×1600 时 `x=36..2524.5`）：

| 记号 | 含义 | 怎么量 |
|---|---|---|
| `bL / bR` | 整条最左 / 最右（两环外沿能到的极限位置） | 扫一行灰亮段 |
| `cL / cR` | 左环**圆心** / 右环圆心 | 同上，取环中心 |
| `W = cR₀ − cL₀` | 全片时两环心距 = **条的有效宽** | 缩到整片量一次 |
| `w = (cR − cL) / W` | 亮段宽占整条的比例 | 由上面算 |
| `xc = ((cL+cR)/2 − cL₀) / W` | 亮段中心在条上的归一化位置 | 由上面算 |
| `u = (t1 − t0) / dur` | 区间占整片的比例 | 从时间码读 |
| `c = (t0+t1)/2` | 区间中心时间 | 从时间码读 |

> 量的时候**不要**把环的外沿和圆心混用：外沿比圆心各宽 5 px（环径 10），混用会引入 ±0.4% 的系统误差。

### 2.3 30 s 素材（2026-10-22，1280×800）

缩到最短时 `W = 1239`、两环外沿距 22 px、可视范围 `V = 1.447 s = 43.4 帧`、`w = 22/1239`。
⇒ 区间跨度 `S = w·V ≈ 0.77 帧`（Pr 的下限是 1 帧）。

> 区间跨度 = `w·V`。r46 早期把二者搞混过一次，导致"Pr 最小 43 帧"的错误结论，已在本表纠正。



## 3. 反推的数学

### 3.1 宽度：幂律

```
w = u ^ p                     u = (t1 − t0) / dur
```

p 由任意一档反解：`p = ln w / ln u`。实测 p 不是常数：

| 素材 | u=0.5 | u=0.25 | u=0.125 | u=0.0625 | u≈0.0017 |
|---|---|---|---|---|---|
| 短片（≈30 s） | 1.301 | 1.314 | 1.341 | 1.406 | — |
| 60 min | 0.478（五档均值，单档 0.468–0.492） | | | | |

### 3.2 为什么 p 随片长变（物理直觉 + 反推式）

Pr 必须保证**最小可视跨度在条上仍是一个能抓的宽度**（约 10–22 px）。设条宽 `RW`（像素）、
最小档宽度 `W0` 像素，则最小档 `u_min = V_min / dur` 要满足 `u_min^p = W0 / RW`：

```
p = ln(W0 / RW) / ln(V_min / dur)
```

- 片长 ↑ ⇒ `ln(u_min)` 更负 ⇒ 分母绝对值变大 ⇒ **p 变小**（曲线变平坦）。
- 这解释了两个实测值：短片 p≈1.30、长片 p≈0.478 不是矛盾，而是同一套约束解出的两个点。

**mpv 侧采用的就是这条反推式**（不是拟合常数）：

```
pow = ln( tl_ov_min_px / rw ) / ln( minspan / dur )
```

- `tl_ov_min_px = 27`（最小档目标宽度：环径 14 + 中间横条 13）
- `minspan = tl_min_span()`（默认 40 帧）
- `rw` = 概览条可用宽度（随窗口变）

⇒ 最小档**恰好**画成 27 px，不需要"撑开"；副产品是 pow 自动随片长变化
（30 s ≈1.24、60 min ≈0.47，与 Pr 实测 1.33 / 0.478 几乎重合）。

反推不成立时（`rw` 未知、`minspan ≥ dur`、越界）回退 `log10(片长)` 插值，夹在 `[0.42, 1.40]`。

### 3.3 中心：线性放大 + 贴边钉死

```
xc = 0.5 + ( c − 0.5 ) · k(u)          c = (t0+t1)/(2·dur)
```

- 短片 `k(0.5) = 1.19`，且 k 与位置 c 无关（§2.1）。
- 深缩时 k 递减（NS4 两轮：`u=1/2→1.19`、`1/4→1.1186`、`1/8→1.074`、`1/16→1.046`），
  拟合为 `k(u) = 1 + (k05 − 1)·(u/0.5)^0.68`，`k05 = tl_ov_k = 1.19`。
- 长片实测方向相反（k = 0.52–0.96 < 1），见 §6 复盘。

**贴边不能走中心公式**：`xc ± w/2` 一旦越界就得夹取，而夹取会把"本该不动的那一端"带着挪。
Pr 的做法是**直接钉死那一端**：

```
at_head（t0 ≤ eps）:  (l, r) = (0, w)
at_tail（t1 ≥ dur−eps): (l, r) = (1−w, 1)
两者都贴:              (l, r) = (0, 1)
```

`tl_ov_edge='pr'` 时改用连续中心公式 + 平移夹取（贴边瞬间不阶跃，代价是那一端有 6–21 px 漂移）；
默认 `'pin'` = 与 Pr 一致。

## 4. mpv 侧实现（r47）

### 4.1 五个函数的分工

| 函数 | 位置 | 干什么 | 关键约束 |
|---|---|---|---|
| `TL.bar_k(u)` | `source-markers.lua:2962` | 中心斜率 | `u≥0.5` 返回 `tl_ov_k`，否则 `1+(k5−1)(u/0.5)^0.68` |
| `TL.bar_pow(dur)` | `:2973` | 宽度指数 | 反推优先；数字 `tl_ov_pow` 可强制固定值 |
| `TL.bar_geom(t0,t1,dur)` | `:2995` 起 | 画 + 命中 | 贴头/贴尾钉死那一端 |
| `TL.bar_solve_px(dur, anchor, target, side, minw, edge)` | `:3086` | 像素钉死反解 | `side` 与 `edge` 必须同时匹配才走贴边式子 |
| `TL.bar_solve(dur, fixed, target, side)` | `:3030` | 时间域二分 | 越界自然收敛到端点，不返回 nil |

### 4.2 绘制链路

```
TL.bar_geom(t0,t1,dur)  ──►  轨道上画亮段 / 两环
        │                         │
        └──► 鼠标命中判定 ◄────────┘   （同一份几何，不许各算一遍）
```

### 4.3 拖动链路（不漂的三条纪律）

1. **抓取时记锚**：抓右环 ⇒ 左端 `gr.l0` 是锚；抓左环 ⇒ 右端 `gr.r0` 是锚。
2. **反解用像素、不硬钳**：`target = (mx − x0) / rw`（只钳到 `[-0.5, 1.5]`），
   交给 `bar_solve_px(dur, anchor, target, side, wmin, edge)` 解出 `(pa, pb)`。
3. **越界按整片收口**：`b − a > 1` 时钳成 1（**不能** `return nil`，否则调用方回落旧式子 ⇒ 端点卡死）。

`wmin = (minspan / dur) ^ bar_pow(dur)` —— 反解与绘制必须用**同一个 pow**，否则窄档时圆环与鼠标错位（= 漂移）。

### 4.4 参数表（`source-markers.lua` 选项区）

| 选项 | 默认 | 含义 |
|---|---|---|
| `tl_ov_map` | `bar` | `linear` 是旧口径（等距时间轴） |
| `tl_ov_pow` | `auto` | `auto` = 反推；给数字 = 强制固定指数（对照用） |
| `tl_ov_k` | `1.19` | 中心斜率（u≥0.5 段） |
| `tl_ov_pin` | `px` | 拖动时钉住端按像素（`time` 为时间钉死） |
| `tl_ov_edge` | `pin` | 贴边钉死（`pr` = 连续中心 + 夹取） |
| `tl_ov_min_px` | `27` | 最小档目标宽度（环心距） |
| `tl_min_frames` | `40` | 最小跨度（帧） |
| `tl_min_mode` | `frames` | `px` 回退旧口径（恒 ≈8% 片长） |

## 5. 拿这套公式怎么用

- **想改外观宽度曲线**：只改 `tl_ov_min_px`（"最小档多宽"），pow 会跟着反推，不用手动调。
- **想强制某个 pow 对照**：`--script-opts=source-markers-tl_ov_pow=1.30`。
- **想验证某档位置**：跑 `tools/probes/probe-geo.lua` 拿 `x0/rw`，用 `bar_geom` 的式子手算 `l,r`，与截图的环心对。
- **想换屏幕重标定**：按 §7 走，只重测 `W`（全片时两环心距）与几档 `w`。

## 6. 复盘：NS1–NS4 的数据为什么"没在控制条上用上"

**结论：不是采集错误，也不是回归错误，是"用一个片长下的常数去套所有片长"的建模错误。**
三条，每条都能用数据对上。

### 6.1 宽度指数：数据被用了，但只用了第一档

- NS1 五档反解出的 p 是 **1.301 / 1.314 / 1.341 / 1.406** —— 数据本身就在说"p 不是常数"。
- 实现取了第一档 **1.30 写成常数**（`tl_ov_pow=1.30`）。u=0.5 处几乎无误差（0.0003），
  但 u=1/16 处偏宽 17 px；换到 60 min 素材（真实 p=0.478）偏得更多 —— **这是"长片上条总是不对"的主因**。
- r47 改成反推后才对上（60 min 五档：我方 0.8878/0.5745/0.5016/0.1566/0.0507，
  Pr 0.8878/0.5714/0.4976/0.1457/0.0436）。

### 6.2 中心斜率：NS3b 精确支持 1.19，但 1.19 只对短片成立

- NS3b 五点反解 k = **1.188 / 1.188 / 1.190 / 1.189**，与 `tl_ov_k=1.19` 完全一致 ⇒ 数据用对了。
- 但 60 min 实测 k = **0.624 / 0.658 / 0.874 / 0.962**（全部 < 1，方向相反）。
- 也就是 k 和 p 一样是**片长的函数**，实现把它当常数 ⇒ 长片上位置偏移、短片上反而"过冲"。
  **这一条 r47 没改**（改中心映射风险大、且缺长片的可靠标定），列为待办。

### 6.3 边界与下限：当时"有意不模仿 Pr 的不自洽"，但代价被低估

- NS4 测出 Pr 的第 5 次 `=` 只缩 0.72 倍、回程还会跳级（见 `测量工作表-NS1NS4.md` §4 判读表）。
- 当时判定"Pr 自己不自洽，不模仿"，把下限改到 15 帧、级别永远可逆 —— 逻辑更干净，
  但用户要的是"像 Pr 一样能缩到 40 帧左右"，于是 r47 又把下限改回 40 帧。
- 教训：**当用户拿 Pr 当基准时，"比 Pr 更自洽"也是一种不一致**，先对齐再谈改进。

### 6.4 遗留待办（写在这里防止再丢）

1. `k(u)` 按片长分离：短片段用 1.19，长片段应按实测 ≈`1 − 0.65·u^0.45`。需要补一次 60 min 的
   **非贴边五点**测量（本轮只有 4 档、且位置靠外推），才能定分段函数。
2. 30 s 素材上 `p` 只有一档实测（u≈0.0017），中段（u=0.1~0.5）没有交叉验证。
3. `tl_ov_edge='pr'` 的连续口径保留着，但没有回归用例覆盖。

## 7. 换屏幕 / 换 Pr 版本后的重标定步骤

1. `gui_screen` 确认分辨率与 dpi（本机曾被改过一次，坐标全部失效）。
2. 缩到整片，截源监视器 → 扫一行得 `bL / bR`，再取两环圆心 `cL₀ / cR₀` ⇒ `W = cR₀ − cL₀`。
3. 按 `=` 缩到 1/2、1/4、1/8、1/16，各量 `cL / cR` ⇒ `w` 与 `p = ln w / ln u`。
4. 播放头放 5 个时间点（覆盖片头、片尾、正中），各按一次 `=`，量 `cL / cR` ⇒ `xc` 与 `k`。
5. 换一部**不同片长**的素材（30 s / 60 min 各一）重复 2–4 ⇒ 才能看出 p、k 随片长的走向。
6. 量法：**环外沿**量 `bL/bR`、**圆心**量 `cL/cR`，不要混用（差 ±5 px ≈ ±0.4%）。
7. 两点法量出的 `s×条宽` 是**可视范围**，区间跨度还要再乘 `w`。
