# Pr 概览条 / 最小可视范围 实测与核验（2026-10-21 夜 ~ 10-22 晨）

> 用途：给「最小跨度（能缩多细）」定量的依据。r47 动手前先读这份。
> 姊妹文档：`设计-第9条-时间轴与面板.md`（§最小跨度与 Pr 的视图）、`测量工作表-NS1NS4.md`（NS1–NS6）、`_tmp` 里的探针脚本已在 §5 列名。

## 0. 一句话结论

**Pr 能缩多细，与片长无关**：30 s 素材的最小可视范围 ≈ 1.45 s（43 帧），60 min 素材的最小可视范围 ≈ 6.2 s（148 帧）。
而 mpv 现在的最小跨度 = 画布 40 px 对应的比例 ⇒ **恒定 8% 片长**（1 h → 290 s / 8714 帧）。这就是"1 h 素材只能到 5 min"的根因。
**修法**：把 `tl_min_span()` 的像素下限拿掉，改用固定帧下限（`tl_min_frames`，建议 40 f）。概览条的"亮段太窄抓不住"改用显示层的最小可见宽度解决，不要拿它当跨度下限。

## 2. 60 min 素材（`ref-CFR-23976-60min.mp4`，dur = 01:00:10.02 = 3610.02 s，23.976 fps）

读法：点 `(x, 675)` 两点读时间码 ⇒ 斜率 `s = (T2−T1)/(x2−x1)` ⇒ **可视范围 `V = s × 1239`**；
环位置由 y=690..700 的灰亮段求出 ⇒ `w = 环距/1239`。

| 档 | V（可视范围 s） | w = 环距/1239 | 反推区间 S = w·V（s） | S（帧 @23.976） |
|---|---|---|---|---|
| G5 | 2800 | 0.8878 | 2486 | 59590 |
| K3 | 1106 | 0.5714 | 632 | 15151 |
| G4 | 825 | 0.4976 | 411 | 9845 |
| G3 | 68.6 | 0.1457 | 10.0 | 240 |
| G2 | 6.17 | 0.0436 | 0.269 | **6.4** |

⇒ **60 min 素材的区间能缩到 ~6 帧**（G2 档），可视范围 6.17 s。两环间距 w 在 G2 = 0.0436 = 54 px（还没贴住 22 px 的下限）。

经验幂律（仅作内插用，别当物理定律）：`w = (V/dur)^b, b = 0.478`（5 档 0.468~0.492）。
中心位置 `xc = 0.5 + (c/dur − 0.5)·k(u)`，拟合 `k(u) = 1 − 0.690·u^0.457`（u = V/dur），5 档自洽到 ±0.0004。
**b 随素材变**：30 s 素材两点定出 b ≈ 1.33（见 §3）—— 所以 `pow=1.30` 不是普适常数，别再用它推最小跨度。

## 3. 30 s 素材（`标尺素材-30s-30fps.mp4`，900 帧 = 30.000 s，30 fps）

操作：在 y=693 抓住左环 `(20,693)` 拖到 `(1240,693)`（steps 45 / delay 25 ms），Pr 把视图压到最小。

- 拖后：环中心 x = 897.5 与 919.5 ⇒ **环距 22 px**（= 两环外沿相切的下限），w = 22/1239 = 0.01776
- 点 `(300,675)` → `00:00:20:27`；点 `(900,675)` → `00:00:21:18`
  ⇒ ΔT = 0.7 s / 600 px ⇒ s = 0.0011667 s/px ⇒ **可视范围 V = s × 1239 = 1.447 s**
- 反推区间：`S = w·V = 0.01776 × 1.447 = 0.0257 s = 0.77 帧` ⇒ Pr 的区间下限就是 **1 帧**
- 可视范围 1.447 s = **43.4 帧 @30 fps** ← 这就是用户说的"缩到最短接近 30~50 帧"

## 4. 核验（这一节是重点：早期结论有一处错，已纠正）

1. **V=1.447 s 是"可视范围"，不是"最小跨度"。** 早期口头汇报把 `s × 1239` 当成区间跨度（说"最小跨度 1.445 s ≈ 43 帧"）—— 错。区间跨度要乘 `w`：`S = w·V ≈ 0.8 帧`。43 帧指的是**可视范围**。用户说的"40~50 帧"同样指可视范围（那个条上能看到的时长）。
2. **V 不可能超过片长**：V=1.447 s ≪ 30 s ✓；反证若把 S 当 1.445 s，则 V = S/w = 81 s > 30 s，自相矛盾 ⇒ 上述更正成立。
3. **w = S/V 的线性关系自洽**：60 min G2 档 S=0.269 s、V=6.17 s ⇒ w=0.0436，与实测 0.0436 一致（这是定义式，只证明内部无矛盾，不是独立验证）。
4. **"最小可视范围与片长无关"成立**：30 s → 1.45 s；60 min → 6.17 s（片长差 120 倍，V_min 只差 4 倍）。而 mpv 现状是 `V_min = 8% 片长`（线性放大 120 倍）。
5. **两环 22 px 是视觉下限，不是跨度下限**：22 px = 两环相切，与 V 无关。60 min 的 G2 档 w=54 px 说明 Pr 还没让它贴到 22 px，所以 60 min 的"最深档"其实还没测到底。

## 5. 遗留与下次补测

- **60 min 素材没拖到底**：应用 §3 的"抓左环拖到最右"办法，看能否把 V 压到 1.5 s 量级（预期可以 ⇒ 与 30 s 素材的 V_min 同量级）。
- **S 没有独立测量**：`S` 全部由 `w·V` 反推。若要独立验证，得在 Pr 里读入点/出点时间码（源监视器"标记"面板或时间码旁的"入点/出点"读数）。
- **b 随素材变的原因未定**：可能是环的像素下限 + 视图自动缩放共同作用，不打算再追（对实现无影响，因为我们不复刻 Pr 的环距曲线，只对齐"最小跨度与片长无关"）。
