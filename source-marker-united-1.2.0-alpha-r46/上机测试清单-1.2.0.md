## 第 9 条 r49/r50 总体验机（概览条：位置线性 + 长度幂律 + 高分屏）—— **验机只看这一节**

> **本轮改了什么**：概览条的**位置**改成严格线性（`环心 x = 轨道左端 + 轨道宽 × 时间 / 总时长`），
> **长度**改成幂律（`w = u^p`，p 由「最小跨度正好画成 22 逻辑 px」反推）。
> 位置和长度分开，是因为你要的四条：拖到最长 = 全片、拖到最短 = 40 帧、平移时线性跟手、撞端点就是片头片尾。
>
> **为什么这样改**：Pr 上实测了 3 个片长（30 s / 5 min / 30 min）共 36 个点 —— 概览条对标的是
> Pr 的**可视范围滑块**，长度非线性；而位置（中心）严格跟时间走。纯线性的旧方案（r49 第一版）
> 会让条在高缩放等级下缩到 0，中间横轴拖不动。
>
> **三条会看到的变化，都不是 bug**：
> ① 长素材（30 min / 60 min）缩到很小时，条**比线性宽**；短素材（30 s）**比线性窄**。
> ② 最小档仍是 22 逻辑 px（800p@100% 就是 22 物理 px，1600p@175% 是 38 物理 px）。
> ③ 缩到很窄时**环会贴在端点上，但那一端的时间不是 0/全长** —— Pr 的滑块本身也是这样（实测偏 13%~21% 轨宽）。
>
> ⚠️ 上一版清单里凡是说「亮段长度 = 区间占比」「两端距离相等」的条目**全部作废**，以本节为准。

### A. 位置跟着时间走（中心线性）

- [ ] 缩成中间区间（1/4 ~ 3/4）：亮段大致居中，两侧留白接近但不要求严格相等（幂律下宽度会伸出去一点）
- [ ] 区间设成 `0 ~ 一半`：**左环心正好压在轨道最左端**
- [ ] 区间设成 `一半 ~ 片尾`：**右环心正好压在轨道最右端**
- [ ] 同一个区间来回缩放、来回拖动后放回原处：环**回到同一像素**，不累积漂移
- [ ] 区间宽度固定为 10%，依次放在 0% / 25% / 50% / 75% / 90%：环心位置**等差移动**（不是越靠边挤得越紧）

### B. 长度按幂律（重点）

- [ ] **30 min 素材**缩到很小区间：**不会再出现「明显不是全片、亮段却几乎占满轨道」**
- [ ] **30 min 素材**缩到一半跨度：亮段**明显长于**轨道的一半（p<1，约 0.7 轨宽）
- [ ] **30 s 素材**缩到一半跨度：亮段**明显短于**轨道的一半（p>1，约 0.41 轨宽）—— 与 Pr 一致
- [ ] **与 Pr 对标**（最硬的验收）：同一个 mp4，在 Pr 里按 `=` 连续缩放，记下「按几下到最小」；
      切回 mpv 用同样素材按 `=` 缩，**到最小的按键次数应该同级**（Pr 30 s = 5 下、5 min = 8 下、30 min = 11 下）

### C. 最小档与拖圆

- [ ] 缩到最窄：两环之间仍有可见横条，**两个环都点得中**
- [ ] 最窄档抓**右环**往右拖：**左环一像素都不动**，右环跟手
- [ ] 最窄档抓**左环**往左拖：**右环一像素都不动**
- [ ] 最窄档继续往外拖到顶：区间**整体平移**（跨度不会小于最小跨度）—— 这是设计，不是锁死
- [ ] **长素材（30 min）全程拖右环**：从最小拖到全片，中间**不会卡住、不会突然跳到别处**
