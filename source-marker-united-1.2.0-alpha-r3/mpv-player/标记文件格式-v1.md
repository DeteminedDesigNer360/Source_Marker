# Source Markers 标记交换格式 v1

**状态**：v1 已冻结（2026-10-06）。写入方：`player-plugin/source-markers.lua`（mpv 插件）。
读取方：Premiere Pro 的 **Source Marker** CEP 面板（`extension/client/main.js`）。
本文件是两侧共同的契约；任何一侧要改格式，先改这里。

---

## 0. 设计目标与取舍

| 目标 | 做法 |
|---|---|
| 跨机器可读、不依赖播放器/工程上下文 | CSV 的时间默认写成**毫秒**（`HH:MM:SS.mmm`），与帧率无关 |
| 无损往返（导出→再导入→再导出逐字节一致） | JSON 为**有损为零**的载体：秒 + 时间码 + 帧率 + 源文件都在 |
| 人可读、Excel 能直接打开不乱码 | CSV = UTF-8（带 BOM）+ CRLF + RFC4180 转义 |
| 对已有工具向前/向后兼容 | 读取方必须忽略未知列/未知字段；写入方只写本规范定义的列 |
| 帧精确不丢 | 毫秒精度是 25fps 下 1 帧的 1/40，任何帧率都不会因取整而偏移 |

**一个刻意的决定**：CSV 默认**不写** `HH:MM:SS:FF`。因为 `FF` 的解释依赖读取方拿到的帧率
（Pr 面板用的是素材 `footageInterpretation.frameRate`）；一旦播放器报的帧率与 Pr 的解释不同
（VFR、丢帧、或解释差异），标记会**静默偏移**且很难发现。需要时间码的人可以显式打开
`time_format=ff`，并自行保证两侧帧率一致；JSON 里始终同时带 `time`（秒）与 `tc`（时间码）。

## 1. CSV（规范格式，写入方默认产出）

### 1.1 字节层

| 项 | 规定 |
|---|---|
| 编码 | UTF-8 |
| BOM | 写入方**默认写 BOM**（让 Excel 正确识别中文）；读取方**必须容忍**开头 BOM（`EF BB BF`）。可用 `csv_bom=no` 关闭 |
| 换行 | 写入方用 CRLF；读取方接受 CRLF / LF / CR |
| 分隔符 | 规范为 `,`；读取方自动判别 `,` `;` `\t`（取首行里出现最多者，制表符优先） |
| 转义 | RFC 4180：字段含 `"`、`,`、CR、LF 时整字段加双引号，内部 `"` 写成 `""` |

### 1.2 列

首行必须是表头。**规范写入方只写这 4 列**：

```csv
time,name,comment,color
```

| 列 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `time` | string | 是 | 见 §3。规范写入方默认写 `HH:MM:SS.mmm` |
| `name` | string | 否（留空） | **保留列，读取方整列忽略**（说明见下）。规范写入方一律写空 |
| `comment` | string | 否（可为空） | 描述正文，可含换行（转义后） |
| `color` | int | 是 | Pr 标记色索引 `0..7`，见 §4。缺失时按 `0` 处理 |

**读取方必须忽略未知列**（向前兼容）；但**写入方禁止**新增任何命中读取方"时间/名称/描述/颜色"
别名正则的列——那会覆盖正列（例如多写一个 `tc` 列会让读取方改用该列取时间）。安全的扩展列只有
名字与别名表完全不沾边的，例如 `color_name`、`source_id`。

> **关于 `name` 列（保留列，读取方忽略）**
> 这一列是历史遗留的占位列：写入方过去在里面填 `M01`、`M02`…，读取方再按 `/^M[0-9]+$/i`
> 把它丢掉 —— 一来一回不携带任何信息，已整体删除。现在的约定：
> - **读取方整列忽略 `name`**：标记名只取 `comment`；`name` 既不参与命名，也不进标记注释；
> - 写入方**保留这一列**（表头四列与列序不变，见 §1.2），但内容写空；
> - 因此 `name` 里放什么都不会影响导入结果 —— **不要把信息放在这一列**，
>   用户可见的文字一律写进 `comment`（Pr 显示的就是 `comment`）；
> - 旧文件（`name` 里带 `M01`）仍能正常导入：那一列现在被忽略，不会跑进标记注释。

### 1.3 行序

写入方按 `time` 升序；同一时间允许多条。读取方**不得**依赖顺序。

### 1.4 样例（含转义）

```csv
time,name,comment,color
00:00:01.240,,"他说""过曝"",第2条",2
00:00:03.520,,曝光过了，需要重新调色,1
00:00:05.120,,背景音有杂音,4
00:00:07.040,,需要补一帧,6
```

## 2. JSON（规范格式，无损）

写入方同时产出 `.json`（与 `.csv` 同名不同后缀）。**UTF-8，不带 BOM**（JSON 规范不容 BOM）。

```json
{
  "format": "source-markers",
  "version": 1,
  "created": "2026-10-06T11:30:00+08:00",
  "source": { "file": "D:\\rushes\\A001.mp4", "fps": 25.0, "durationSec": 600.0, "timeFormat": "ms" },
  "markers": [
    { "time": 1.240, "tc": "00:00:01:06", "name": "", "comment": "他说\"过曝\",第2条", "color": 2 },
    { "time": 3.520, "tc": "00:00:03:13", "name": "", "comment": "曝光过了，需要重新调色", "color": 1 }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `format` | string | 建议 | 固定 `"source-markers"`，用于识别 |
| `version` | int | 是 | 本规范 = `1` |
| `created` | string | 否 | ISO-8601 带时区 |
| `source.file` | string | 否 | 播放器打开的原始文件路径 |
| `source.fps` | number | 否 | `null` 表示未知（VFR 时为容器帧率的近似值） |
| `source.durationSec` | number | 否 | 素材时长 |
| `source.timeFormat` | string | 否 | 写入方**请求**的时间格式：`ms`/`ff`/`sec`/`auto`（`auto` = 整数帧率且非 VFR 时用 `ff`，否则用 `ms`） |
| `markers[].time` | number | 是 | **权威值**：秒（浮点，≥0），保留 3 位小数 |
| `markers[].tc` | string | 否 | 展示用时间码；**读取方若已有 `time` 必须忽略它** |
| `markers[].name` | string | 否 | 同 CSV：保留字段，读取方忽略，写入方写空 |
| `markers[].comment` | string | 否 | 同 CSV |
| `markers[].color` | int | 是 | `0..7`，同 CSV |

**读取方兼容要求**：

- 接受三种包裹：裸数组 `[...]`、`{"markers":[...]}`、`{"data":[...]}`（Pr 面板三种都支持）；
- 忽略一切未知字段；
- `version` 大于自身支持上限时：**告警但仍尽力解析**（不要直接拒绝）；
- 字段取值等价：某条标记的 `time` 缺失时，依次尝试 `tc` → `start` → `startTime`（Pr 面板的现有行为，
  本规范把这条固定下来，便于其它工具生成）。

JSON Schema 见 [`marker-format.schema.json`](marker-format.schema.json)。

## 3. 时间表示

| 形式 | 例 | 读取方要求 |
|---|---|---|
| `HH:MM:SS.mmm` | `00:00:03.520` | 必须支持（规范默认） |
| 纯秒 | `3.520` | 必须支持；`-` 开头的负数视为非法（写入方禁止产出） |
| `MM:SS` | `03:31` | 必须支持（`分:秒`，秒可带小数） |
| `HH:MM:SS:FF` | `00:00:03:13` | 必须支持，但**需要帧率上下文**；`FF` 必须 `< ⌈fps⌉` |
| `HH;MM;SS;FF`（丢帧） | — | **不支持**（Pr 面板按 `:` 切分）。丢帧素材请用毫秒 |

- 帧率来源：Pr 面板用当前源素材的 `footageInterpretation.frameRate`；播放器插件用 `container-fps`
  （退化到 `estimated-vf-fps`）。**两侧帧率不一致时 `FF` 会算错，这是选择毫秒作默认的原因。**
- 毫秒 → 秒的误差必须为 0（不引入任何浮点漂移）。
- **生成 `HH:MM:SS:FF` 的算法（写入方必须照此实现，勿改回"总帧数取模"）**：
  `SS = floor(sec)`（整秒），`FF = round((sec - SS) × 真实fps)`，若 `FF ≥ ⌈fps⌉` 则进位 `SS+1, FF=0`；
  且 `sec < 0` 一律按 0 处理。
  这样 Pr 的 `SS + FF / 真实fps` 才能反解回原秒（误差 ≤ 半帧）。
  历史上的错误做法是"先算总帧数 `round(sec×fps)`，再按 `round(fps)` 取模拆位"——它在 29.97/23.976 上
  会线性漂移（300s 偏 ~9 帧、600s 偏 ~18 帧），已被回归测试 `run-ntsc-test.ps1` 钉死。
  （Pr 面板自带的 `secondsToTimecode()` 是给界面显示用的，用的是总帧数法；**跨载体交换**必须用上面这套。）

## 4. 颜色

`color` 是 Premiere 的标记色索引（`Marker.setColorByIndex(n)`）：

| 索引 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 名称 | 绿 | 红 | 紫 | 橙 | 黄 | 白 | 蓝 | 青 |
| 参考色值 | `#1FA84C` | `#E5484D` | `#9B51E0` | `#F2994A` | `#F2C94C` | `#F2F2F2` | `#2F80ED` | `#56CCF2` |

- 写入方：必须输出 `0..7` 的整数；缺省 `0`（绿）。
- 读取方：`0..7` 必须正确落色；超出范围或非数字时**退回 `0` 并告警**，不得中断整份导入。
- 参考色值只用于播放器 OSD 与文档展示，**不参与交换**（文件里只有索引）。

## 5. 其它可导入格式（仅导入，非规范）

为方便从别的工具过渡，读取方还应接受：

| 格式 | 规则 |
|---|---|
| TSV / 分号分隔 | 与 CSV 同规则，分隔符不同（自动判别） |
| 无表头 CSV | 按位置取列：`时间, 名称, 内容, 颜色` |
| 中文表头 | `时间码/时间/时间戳/起始`、`名称/标题/标签`、`备注/内容/描述/说明`、`颜色` |
| SRT | 取每条字幕的起始时间；字幕文本作为 `comment`；`name` 空、`color` = 0 |
| 英文别名表头 | `time/tc/timecode/start/in/timestamp`、`name/title/label`、`comment/desc/description/content/text/note`、`color/colour` |

内容嗅探顺序：首字符 `{`/`[` → JSON；匹配 `序号 + HH:MM:SS,mmm -->` → SRT；否则按分隔符表格解析。

## 6. 一致性与错误处理

**写入方保证**：

1. 导出 → 再导入 → 再导出：**CSV 逐字节一致**（幂等）；JSON 除 `created` 时间戳外内容一致；
2. `time` 保留到毫秒且不被浮点误差改写；
3. CSV 里不会出现未转义的 `"`、CR、LF；
4. 空标记列表时**不产出文件**（播放器会提示"还没有标记可导出"）；
5. `color` 只会是 `0..7` 的整数（越界/非数字/`NaN` 一律按 0 处理并告警），`time` 不会是负数。

**读取方保证**：

1. 单条标记坏 → 跳过该条**并告警**（报告跳过条数），**不放弃整份文件**；
   `{"markers":123}` 这类形状不对的 JSON 也只会得到「0 条标记 + 告警」，不得抛异常中断
   （mpv 插件曾被这条坑到整会话失效）；
2. 表头缺失/列缺失 → 按别名与位置规则尽力解析；
3. BOM、CRLF/LF、多余空行、行尾空白都必须被容忍；
4. 颜色非法 → clamp 到 `0..7`（非数字/`NaN` → 0）并告警；时间为空 → 跳过；
5. **换行会被折叠**：文件层允许 `comment` 含换行，但 Pr 面板的内部传输协议用 `\n` 当记录分隔符，
   因此面板在送入宿主前把字段里的 CR/LF/US(`\x1f`) 折叠成空格（`extension/client/main.js` 的
   `buildImportPayload()`）。要保留多行原文，请保留导出的 CSV/JSON 文件本身（文件层不丢字符）。

---

## 7. 版本与兼容策略

- `version` 为主版本号，整数。**新增可选字段/列 = 仍是 v1**；删改语义 = 升 v2。
- 读取方：`version ≤ 支持上限` 正常解析；更大的版本 → 告警 + 尽力解析。
- 写入方：只写本规范 v1 定义的内容，不写"未来才有的"字段去试探读取方。
