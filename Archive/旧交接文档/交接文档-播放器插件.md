# Source Markers 播放器插件 · 移交文档（开发历程 / 经验 / 错误）

**用途**：把「mpv 播放器侧」的产物与踩坑经验移交给下一个工作区，用于**两个插件的合并**。
**日期**：2026-10-06 ｜ **插件版本**：1.0.0 ｜ **宿主**：mpv 0.41.0（官方 Windows x64 构建）
**姊妹文档**：Pr 面板侧的移交文档是同目录的 [`交接文档.md`](交接文档.md)。
**两份合起来才是完整交接** —— 那份讲 Pr 扩展（读取方）与仓库全景，这份讲播放器插件（写入方）。

> ⚠️ 本文件是**另一工作区（播放器侧）**写的；`交接文档.md` 由 Pr 面板侧维护，**请勿互相覆盖**。

## 0. 接手前必须知道的三件事

1. **这是一个"写入方 → 读取方"的双侧系统**：播放器插件产生标记文件，Pr 面板把它读成标记。
   两侧靠 `docs/marker-format.md`（格式 v1）耦合，**任何一侧单方面改格式都会静默地把标记放错位**。
2. **最有价值的资产不是代码，是 §3 那批被实测推翻/证实的 mpv 行为**。它们既不在 mpv 文档的显眼处，
   也没法靠"读代码"发现；重来一遍要再花十几次真机往返。
3. **mpv 里一个未捕获的 Lua 错误 = 该脚本客户端被销毁**：键位注销、所有 script-message 失效、
   sidecar 不再保存（用户看到的现象是"按键没反应"）。**所有解析/IO 路径都必须 pcall 兜底** —— 这不是洁癖，
   是分布出去之后最容易被用户触发的故障（见 §3 第 10 条、§5.1）。

## 3. 核心资产 A：被实测推翻 / 证实的 mpv 行为

> 全部在本机实测（mpv 0.41.0 官方构建 + mpv 0.36.0 Arctime 自带 + LuaJIT/Lua 5.1）。
> **改插件前务必先读这一节**；每条都写明"直觉 → 实测 → 后果与修法"。

| # | 直觉 / 文档暗示 | 实测 | 后果与修法 |
|---|---|---|---|
| 1 | `seek t absolute+exact` 就是帧精确 | **默认 `hr-seek=default` 会按关键帧对齐**：请求 3.52s 落到 4.16s | 必须 `hr-seek=yes`（插件启动时设置，且**不覆盖用户 mpv.conf 里显式的 `hr-seek=no`**）；暂停后再 seek 实测 3.52→帧 88、7.04→帧 176、1.24→帧 31 全部精确 |
| 2 | 读 `time-pos` 就是"当前播放头" | 不暂停时读到的值会随播放推进：**发起 seek 后等 0.5s 再采样，会偏 +0.52s** | 这是**测法错误**（我一开始据此误判 seek 不准）。打标记必须**即时读取**或暂停后读（§4.1） |
| 3 | `mp.input` 是 `mp` 表上的模块 | **`mp.input == nil`**（0.36 与 0.41 都是）；正确形态是 **`require 'mp.input'`**（≥0.38 才有） | 插件用 `pcall(require,'mp.input')` 探测；老版本退回 Python tkinter 兜底对话框 |
| 4 | `osd-overlay` 的 `ass-events` 收完整 ASS 文档 | **每行会被直接当成一个 Dialogue 的 Text**：塞整份 ASS（`[Script Info]`/`[V4+ Styles]`/Events）→ **头部被当文本画在屏幕上** | 只传事件正文行（`{\an7\pos(..)}文本`），样式由 mpv 提供。**这个 bug 只有截图才能发现**，无头测试全绿也照样错 |
| 5 | 键名 `Ctrl+Delete` 合法 | **非法**：mpv 键名表里只有 `DEL`；且 **`add_key_binding` 对非法键不抛错**，只在日志里打 `Unknown key` | 改为 `Ctrl+DEL`；把"日志里不得出现 Unknown key"写进测试断言 |
| 6 | `expand('~~home/markers')` 总指向配置目录 | **`--no-config` 时退化成相对路径 `markers`** → 插件会在**进程当前目录**里造目录 | 新增 `is_absolute()` / `resolve_dir()`：非绝对路径依次退回 `TEMP\source-markers`；流输入文件名再用 `safe_filename()` 净化（`:`→`_`、Windows 保留设备名、长度上限） |
| 7 | `~~temp` 是有效路径前缀 | **裸前缀不展开**（原样返回 `~~temp`），带斜杠的 `~~temp/` 在本机又解析为空串 | 兜底脚本一律写 `os.getenv('TEMP')`；写不出去要 `notify` 报错，**不能静默失败** |
| 8 | `msg.info('a=%s', x)` 会做 printf | **不会**：mpv 的 `msg.*` 只把参数用空格拼起来，`%s` 原样出现在日志里 | 一律 `msg.info(string.format(...))` |
| 9 | `--script=source-markers.lua` 的脚本名是 `source-markers` | mpv 会**把非字母数字换成下划线** → 脚本名是 **`source_markers`** | 测试/外部工具用 `script-message-to source_markers`；插件内部用 `mp.get_script_name()` 动态取，别硬编码 |
| 10 | Lua 脚本里出错只是打个日志 | **未捕获错误 = mpv 销毁该脚本客户端**：键位全部注销、script-message 全部失效、sidecar 不再保存 | 见 §5.1 与 §2 阶段 7 的 F1；最外层解析函数包 pcall，bad case 退化为"0 条 + 告警" |
| 11 | `mpv.set_mouse_area` 只需一个 section | 区域是按 **section** 生效的，一个 section 无法区分多个按钮 | **每个按钮一个 input section**：`define-section sm_panel_<名字>` + `enable-section` + `set_mouse_area(x0,y0,x1,y1,section)` |
| 12 | 可点击面板只能靠人手测 | **无头也能模拟真实点击**：`mouse x y` + `keypress MBTN_LEFT` 会正确走「鼠标区域 → section → `script-binding <脚本名>/<绑定名>`」 | 面板交互因此**完全自动化**（`run-panel-test.ps1`，43 项）——这是本项目最有用的一条测试技巧 |
| 13 | 用 `enable-section exclusive` 让面板压过 OSC | 语义是"**屏蔽此前所有 section**" → 会把 mpv 的 OSC 整段禁用（连进度条拖动都没了） | **排除该方案**；改用"颜色行放最上 + 面板自动抬到进度条上方（≥20% 屏高 / 90px）+ `panel_anchor` 逃生选项" |
| 14 | `screenshot <flags> <file>` | 0.41 改成 **`screenshot-to-file <file> [<flags>]`**（旧写法报 `Invalid value for option screenshot`） | 测试脚本改用新写法（窗口截图用 `window` flag） |
| 15 | `utils.write_file` 在 Lua 侧可用 | **Lua 的 `mp.utils` 没有 `read_file`/`write_file`**（那是 JS 后端的）；`utils.parse_json`/`format_json` 倒是有 | 文件 IO 用标准 `io.open`；JSON 用 `utils.*`，并保留内置兜底实现 |
| 16 | LuaJIT 有 `utf8` 库 | **没有**（5.1/5.2） | 需要按宽度排版时自己按字节判 UTF-8 长度（面板按钮宽度估算） |
| 17 | mpv 配置项前缀用下划线也行 | `--script-opts=source-markers-x=1`（连字符）生效，**`source_markers-x` 不生效** | 文档与测试统一用连字符 |

### 3.1 附：宿主选型的结论（一句话版）

mpv 独有的是「官方 Lua 脚本 API + 能读播放位置/帧率 + 帧精确 seek + 可交互覆盖层 + 标准 io」；
PotPlayer 闭源无位置 API；MPC-HC/MPC-BE 无插件 SDK（只能外部程序 + MPCAPI/WebUI）；
VLC 有 Lua 扩展但 **Lua 层取不到视频帧率**（`HH:MM:SS:FF` 直接卡住）。详见 `research/01-…md`。

## 4. 核心资产 B：我犯过的错误（过程性教训）

> 这一节比代码更值得读，尤其第 1～4 条都是"以为自己验证过了，其实没验证"的类型。

| # | 错误 | 具体表现 | 正确做法 |
|---|---|---|---|
| 1 | **测法错了，却当成被测对象错了** | 测 seek 精度时"发 seek → 等 0.5s → 读 time-pos"，得到恒定 +0.52s 偏移，据此差点去改 seek 逻辑。真相是**播放仍在推进** | 测时间相关的东西先**暂停**；或用"目标值 vs 实际值"的**不变量**（帧号）断言 |
| 2 | **测试素材覆盖不足** | 全程只测 25fps → 漏掉 29.97/23.976 的 `HH:MM:SS:FF` 漂移（300s 处偏 9 帧、600s 处偏 18 帧），而 25/30 是**完全正确**的 | 时间码/帧率相关必须**跑非整数帧率**；为此单独加了 29.97 素材与回归套件 |
| 3 | **断言写错，冤枉了实现** | `Select-String -Pattern 'nan'` 命中了备注里的 `c_nan` 文本；把 `notify()` 的 OSD 文案当日志断言；`面板已关闭` 读的是**点击前的旧快照** | 断言要**精确到字段/时机**：只看颜色列、只匹配 `msg.*` 写的日志、点击后重新取快照 |
| 4 | **PowerShell 文本管道毁掉 UTF-8 文件** | `Get-Content -Raw \| Set-Content -Encoding UTF8` 会按 ANSI(CP936) 读中文 → 整个测试文件变乱码，只能重写 | 处理中文文本走 `[System.IO.File]::WriteAllText/ReadAllText`、Python，或本仓库 `edit`/`write` 工具 |
| 5 | **`write`/`edit` 会抹掉 `.ps1` 的 BOM** | 中文 `.ps1` 改完就变成"PS 5.1 里语法错误 + 乱码报错"；同一个坑在根 `install.ps1`、`player-plugin\install.ps1`、`run-test.ps1` 上各踩一次 | 新增 `tools/ensure-ps1-bom.ps1` **自愈**并把它作为 `run-all-tests.ps1` 的第一步（对方文档里也有 BOM/编码相关约定） |
| 6 | **打包脚本把 zip 建在它自己正在压缩的目录里** | `ZipFile::CreateFromDirectory($OutDir, $zip)` → `IOException: being used by another process` | 从 stage 目录打包：`CreateFromDirectory($stage, $zip, …, includeBaseDirectory: $true)` |
| 7 | **总入口给不接受的脚本透传参数** | `run-all-tests.ps1` 给 `run-package-test.ps1` 传了 `-MpvDir`（该脚本用包内 mpv，没有这个参数）→ 参数绑定失败 | 每个套件的参数契约写清楚；失败要在汇总里立刻可见 |
| 8 | **"照抄代码"的测试会测到旧代码** | 独立验证者把 payload 构造逻辑**抄**进自己的检查脚本 → 我修了 `main.js` 它仍显示旧行为 | 把被验证逻辑**抽成具名函数放进可切片段**（本项目是 `buildImportPayload`），让测试**加载生产代码**而不是重写 |
| 9 | **文档与实现漂移** | 帮助里写的键位/数量与真实注册的对不上（"17 个快捷键"实际 18 个；文档承诺的行为代码里没有） | 用**单一数据源**：一张 `ACTIONS` 表同时生成快捷键、帮助浮窗、按钮面板；数量从表里算 |
| 10 | **深夜做的"看起来没问题"的 UI** | 第一版把完整 ASS 文档塞进覆盖层（§3.4），无头测试全绿 | UI 必须有**视觉验证**：截图（`screenshot-to-file`）后用图像检查，不能只靠日志断言 |
| 11 | **没考虑真实窗口环境** | 面板放底部 → 被 mpv 进度条遮住，颜色点不到；选中色块用深色文字 → 深底上看不清（**都是用户实测发现的**） | 关键 UI 要问"它在真实窗口里会被什么挡住/对比度够吗"；给逃生选项（`panel_anchor`/`panel_bottom`） |
| 12 | **忘了自己会往 CWD 写文件** | `--no-config` 下 sidecar 路径退化，在工作目录里造了个 `markers\` 空目录（被独立验证者抓到） | 写文件前判绝对路径；测试里加"副作用快照对比"（运行前后 diff 目录） |

### 4.1 一条方法论（与 Pr 侧那份的结论一致）

> 凡是「某个 API 帮我做成了某事」的地方，最终都改成**做完之后把状态读回来核实**：
> 导出后**解析产物**、写完标记后**重新 dump**、声称"sidecar 存了"就去**读文件**、
> 声称"面板点得到"就用**真实鼠标事件**点一次。

| 条款 | 为什么不能动 |
|---|---|
| CSV 表头固定四列 `time,name,comment,color`，**不新增命中别名正则的列** | Pr 解析器按别名映射列；多一个 `tc` 列会**覆盖** `time` 列（静默取错时间） |
| 时间默认写**毫秒** `HH:MM:SS.mmm` | 与帧率无关，跨机器不会偏移；`ff` 模式只在整数帧率才安全 |
| `time_format=ff` 的算法：**整秒 + 真实帧率的帧号**（进位阈值 `⌈fps⌉`） | 禁止改回"总帧数按 `round(fps)` 取模"——那正是 F2 漂移的成因（回归测试 `run-ntsc-test.ps1` 钉死） |
| CSV 带 UTF-8 BOM、CRLF、RFC4180 转义 | Excel 友好；Pr 读取路径会剥 BOM（已在其 `main.js` 里核实） |
| `color` 只能是 `0..7` 整数（越界/非数字/**NaN** 一律 0 并告警） | NaN 比较恒为 false，不特判会写进文件（第二轮 N1） |
| ~~`name` 列**必须存在且非空**，且只放占位名（`M01`…）~~ → **本款已作废** | 原由：Pr 面板用 `/^M[0-9]+$/` 判断占位名。**合并版已整体删除占位符机制**：Pr 整列忽略 `name`，本侧保留该列但写空（见 `source-marker-united-1.0.1-alpha/改动说明.md`） |
| 时间不得为负 | `to_timecode` 对 `sec<0` 一律按 0 处理（第二轮 N3） |
| 坏文件只能降级、不能抛异常 | `parse_marker_file` 外层 pcall；`{"markers":123}` 这类形状曾**打死整个插件**（F1） |

### 5.2 其他红线

- **`source-markers.lua` 是单文件、零外部依赖**（除可选 Python 兜底输入框）。合并时不要拆成多文件脚本，
  也不要引入需要编译的东西——它的价值之一就是"丢一个文件就能用"。
- **`ACTIONS` 单一数据源**：新增功能请往这张表里加（同时得到快捷键 + 帮助 + 面板按钮）；
  不要单独 `add_key_binding` 而不进表，否则帮助/面板会与实现脱节。
- **sidecar 的隐藏属性**（`attrib +h`）与**原子写**（先 `.tmp` 再 rename）保留。
- **便携包默认配置** `release-template/mpv.conf` 里 `script-opts=source-markers-panel=yes`
  （面向新手：打开就有按钮面板）。改这个等于改新手的第一次体验。
- **`tools/pr-parser.js` 依赖对方 `main.js` 的两条注释标记**（对方文档 §5.1）。
  本侧的所有跨侧测试都建在它上面；那两行前缀一变，本侧测试会直接报错（不是静默错）。
- **`run-all-tests.ps1` 会执行 `ensure-ps1-bom.ps1`，它会写文件**（给自己补 BOM）。
  在只读环境/CI 里跑要先知道这一点。

### 7.3 合并检查清单

- [ ] `交接文档.md`（对方）**未被覆盖**；本文件也未被对方覆盖
- [ ] `release/` 写入权已定：各自独立子目录，或单方出包（**别让两边都清 `release/`**）
- [ ] `release/` 里两侧产物都在，且各自 SHA256SUMS 覆盖范围写清楚
      （现有 `release/SHA256SUMS.txt` **只覆盖 Pr 扩展的两个 zip，不含 mpv 包**）
- [ ] 插件哈希未变：`player-plugin/source-markers.lua` = `4e1eb76c…`（若有意改动，请更新
      `player-plugin/README.md` 与 `docs/marker-format.md` 的相关说明并重跑全部套件）
- [ ] `docs/marker-format.md` 若被改动：两侧的读取/写入代码同步改，并重跑 §7.2 的第 1、2 步
- [ ] 两个 zip 解压后逐文件哈希一致（Pr 包用 `install.ps1 -DryRun` 退出码 0；mpv 包用包内 `校验.ps1`）
- [ ] 用户实际用过的标记文件仍能导入（示例：根目录
      `25帧刘华强买瓜修复2.0_markers_20261006-121015.csv` —— 这是用户真机导出的产物，
      `node tools/verify-import.js` 的解析路径可覆盖同类文件）
- [ ] 若合成"一个包"：**先决定**是否把 22 MB 的 mpv 本体与 40 KB 的 CEP 扩展放一起（对方文档 §1 已提示这个顾虑）

### 7.4 合并时最容易踩的两个坑

1. **格式单边改动**：本侧默认毫秒、Pr 侧也认毫秒；如果有人把某一侧改成"只写 ff"，在非整数帧率上会**静默错位**。
   改格式必须同时改两侧 + 跑 NTSC 回归。
2. ~~**`name` 列语义**：本侧只写占位名（`M01`），Pr 侧用"备注"当标记名、并把非占位的 name 移进注释。~~
   **已在合并版中整体废除**：占位符机制删除，Pr 整列忽略 `name`，本侧保留该列但写空。
   保留这条只为说明一个仍然成立的结论：**往 `name` 列写东西不会被 Pr 采用，用户可见的文字必须写 `comment`**。
